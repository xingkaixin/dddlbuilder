# Oxlint tsrs 后端评估

日期：2026-11-18。评估基于提交 `ddf6474e46998ea231a61a45cb0203bb01c28156`。

结论：在本项目中值得切换。完整 `pnpm lint` 的耗时中位数下降 22.5%，CPU 用时下降 34.8%，进程树峰值 RSS 采样下降 17.0%。现有诊断没有变化。机器有后台负载，耗时范围较宽，不能把这个比例当成 CI 的固定收益。

## 变更

- 使用 pnpm 添加并固定 `tsrs@0.25.0-ts7.1.0-beta`，移除根 workspace 对 `oxlint-tsgolint` 的直接依赖。
- Oxlint 保持 `1.94.0`。这是评估时 registry 的最新版，已支持优先自动选择 `tsrs-lint`。
- `.oxlintrc.json`、自定义插件、tsconfig、所有 lint 脚本、扫描范围、警告策略和并发设置保持原样。
- `pnpm typecheck` 继续使用项目原有的 TypeScript 7.0.2。此次只切换 lint 后端，没有合并 lint 与类型检查。

Oxlint 1.94.0 声明了可选 peer `oxlint-tsgolint`。pnpm 在此次更新中仍将其保留在 lockfile 的 peer 依赖图中；它已不是根 workspace 的直接依赖。实际运行的后端通过进程采样确认为 tsrs。

## 环境与方法

- Apple M1 Pro，10 核，32 GiB 内存，macOS ARM64。
- Node.js 24.22.3、pnpm 12.21.0、Turbo 2.11.11、Oxfmt 0.79.0。
- 旧后端：`oxlint-tsgolint@7.0.2007`；新后端：`tsrs@0.25.0-ts7.1.0-beta`，基于 TypeScript 7.1.0-beta。
- 测量完整 `pnpm lint`，包含 Turbo、8 个 workspace 的 lint 与格式检查，以及根目录的 lint 与格式检查。`@ddlbuilder/tsconfig` 没有 lint 任务。
- 设置 `TURBO_FORCE=true`，每次日志均确认 `0 cached, 8 total`。未清空系统文件缓存，各后端均经过预热。
- 两个后端同时安装，在同一源码上按 tsgolint、tsrs 的顺序交替执行，各 10 次。通过绝对路径 `OXLINT_TSGOLINT_PATH` 选择后端；两侧均设置 `TURBO_ENV_MODE=loose`，使 Turbo 子任务收到该变量。这些设置只用于评估，没有写入项目配置。采样未观察到错误后端。
- 最终项目验证使用默认的 Turbo 环境模式和后端自动选择，仍强制执行任务。
- 耗时、累计 CPU 用时和系统报告的最大 RSS 来自 macOS `/usr/bin/time -l`。最大 RSS 不代表并行进程的同时内存总量，因此另外记录了整个子进程树 RSS 之和的峰值。
- 进程树通过 `ps` 采样；采样间隔中位数约 140 ms，范围约 99–452 ms。该指标可能漏过短暂峰值，也会重复计算共享页，不能当成精确的物理内存占用。
- 测量期间没有并行运行项目验证。系统中有备份、编辑器、浏览器和其他 Node 进程，未终止用户进程。因首轮 5 对耗时波动较大，扩展到 10 对，全部样本均纳入统计。

### 耗时来源

单独对 Web 的 542 个文件运行了 `--debug timings --format default`，不纳入性能样本。tsgolint 日志显示构建了包含 2940 个源码文件的 TypeScript program，未匹配文件数为 0。

规则计时中，类型感知回调累计从约 1649 ms 降到 368 ms，其中 `unbound-method` 从约 803 ms 降到 165 ms，`await-thenable` 从约 345 ms 降到 88 ms。新后端确实减少了类型感知分析的 CPU 工作。

普通 Rust 规则、JS 自定义规则、进程启动和格式检查仍然执行。新后端的这次 Web profile 中，JS 插件 runtime 仍约 605 ms，`react/void-use-memo` 规则回调约 308 ms。这些工作限制了完整命令的收益。规则计时会增加开销，且并行回调时间不能直接相加作为墙钟耗时，因此不能用它们推算整体倍数。

## 复现与证据

本次运行的原始日志、JSON 诊断、文件列表、配置哈希、进程采样和测量脚本保留在本地 `.temp/oxlint-tsrs-evaluation/`，该目录不进入 Git。`summary.json` 记录全部样本与汇总，`validation.json` 记录验证退出码。

要重新比较两个后端，可临时安装两者，再使用相同 lint 命令交替运行：

```sh
pnpm add -Dw tsrs@0.25.0-ts7.1.0-beta oxlint-tsgolint@7.0.2007
for run in {1..10}; do
  for backend in tsgolint tsrs-lint; do
    TURBO_FORCE=true TURBO_ENV_MODE=loose \
      OXLINT_TSGOLINT_PATH="$PWD/node_modules/.bin/$backend" \
      /usr/bin/time -l pnpm lint
  done
done
pnpm remove -Dw oxlint-tsgolint
```

上述命令记录 macOS 的耗时和最大 RSS；进程树采样需同时使用本地测量脚本。`compare.py` 会调用 `measure.py` 并保存每次日志与 JSON，使用前需要同时安装两个后端。

参考：[官方介绍与接入方式](https://oxc.rs/blog/2026-11-17-faster-type-aware-linting-with-tsrs)、[Oxlint 1.94.0 后端选择实现](https://github.com/oxc-project/oxc/blob/oxlint_v1.94.0/crates/oxc_linter/src/tsgolint.rs#L1467)。
