# 产品目标与边界

## 定位

DDLBuilder（筑表师）是在浏览器中使用的数据库表结构设计工具。用户用表单和表格定义表结构，实时得到多种数据库方言的 DDL、DCL 和 ORM 模型代码，用于建表前的评审、沟通和交付。

## 目标用户

- 设计新表、需要输出多种方言 DDL 的开发者
- 维护或接手已有数据库，需要理解结构、生成文档、对比差异的成员
- 需要可重复关联测试数据的测试人员
- 手上有 CSV/Excel 业务数据，需要建表或生成导入 SQL 的用户

## 核心工作流

1. 设计与导入：手工编辑字段、索引、外键、分区等，或从 SQL、CSV/Excel 字段清单、JSON Schema、表蓝图模板、AI 生成结果导入。DDL、DCL、视图、Routine 和 ORM 代码随编辑实时生成。
2. 保存与演进：在工作区中管理草稿、已保存表、文件夹和回收站；对已保存表做 diff，生成 ALTER 和回滚 DDL。
3. 交付与理解：数据字典、ER 图（物理外键与逻辑关系）、两份结构的对比与迁移 SQL、项目文档与变更提案、关联测试数据、业务数据导入、查询设计、业务模块、SQLite/D1 初始化项目导出。
4. 账号能力：登录后工作区跨设备同步，可发布项目文档和变更提案，可使用按额度计费的 AI 辅助（建表、改表、索引建议、注释、DDL 评审、SQL 解释）。

## 产品原则

- 本地优先：不登录也能完成设计、导入、生成、只读分享和本地导出。登录只增加同步、发布和 AI。
- 输出供人审阅：生成结果是给人审阅和复制的文本。生成器无法安全推断的变更，要明确提示需要人工处理，不输出看似可执行、实际不完整的 SQL。
- 方言准确优先于覆盖面：新增方言或特性时，以真实语法、保留字和长度限制为准，不用通用 SQL 近似。
- 用户数据最小化：业务数据记录和数据库凭据不离开浏览器。表结构只在用户使用同步、分享、发布、SQL 解析或 AI 时发送到服务端。

## 非目标

下列事项不在产品范围内。要改变其中任何一项，先更新本文档并写明理由。

- 不连接用户的数据库，不执行生成的 SQL，不提供整库数据回滚。
- 不接收或保存数据库凭据、云平台 token。结构只通过 SQL 文本、快照文件和本地导出接入。
- 不输出可直接执行的跨数据库迁移脚本。跨方言只提供兼容性评估。
- 不做审批流或项目管理。变更提案只用于讨论，没有审批状态。
- 不支持多人共同编辑同一个工作区。工作区属于单个用户，同步只服务于该用户的多台设备。
- 业务数据导入不上传记录、不写入工作区、不随账号同步，也不生成 DROP、DELETE 或覆盖写入语句。
- 测试数据规则是声明式配置，不执行用户提供的代码或表达式。
- 不向未登录用户提供 AI。
