# パーティションとシャーディングの設定

このページでは、MySQL 系データベースでテーブルのパーティションを設定する方法と、PostgreSQL (Citus) で分散シャーディングを設定する方法を説明します。

## 利用場面

ログ、過去の注文、時系列データなど、数千万行規模の大きなテーブルは範囲でパーティション分割できます。古いデータをパーティション単位でアーカイブしやすくなり、クエリがスキャンするパーティションの範囲も狭まります。PostgreSQL Citus で水平スケールする場合は、大きなテーブルを分散テーブルとして設定できます。

---

## 設定手順

### 1. MySQL 系データベースのテーブルパーティション
データベースの種類が MySQL、MariaDB、TiDB、OceanBase (MySQL)、GBase、PolarDB の場合、設定エリアの「詳細設定」メニューに「パーティショニング」が表示されます。
1. **パーティショニングを有効にする** スイッチをオンにします。
2. **パーティションの種類** を選びます。
   - **RANGE / RANGE COLUMNS** は、数値の範囲または日付の区間で分割します。たとえば注文テーブルを年ごとに分けます。「年別」「月別」「日別」をクリックすると、パーティション定義をまとめて生成できます。
   - **LIST / LIST COLUMNS** は、個別の値のリストで分割します。たとえば地域や業務の種類ごとに分けます。
   - **HASH / KEY** は、ハッシュ値でデータを指定した数のパーティションに分散します。パーティションに使うフィールドとパーティション数を指定する必要があります。
3. **パーティションキー** にフィールド名または式（`YEAR(created_at)` など）を入力し、各パーティションの境界値を入力します。
4. DDL に対応する `PARTITION BY ...` 句が生成されます。

### 2. PostgreSQL Citus の分散シャーディング
データベースの種類が **PostgreSQL (Citus)** の場合、設定エリアの「詳細設定」メニューに「シャーディング」が表示されます。
1. **テーブルモード** を選びます。
   - **参照テーブル**（Reference Table）は、すべてのノードに完全なコピーを保存します。辞書テーブルや設定テーブルなどの小さなテーブルに向いています。大きなテーブルとの結合クエリをそのノード内で処理できます。
   - **分散テーブル**（Distributed Table）は、分布コラムで水平に分割する大きなテーブルです。**分散列**（Distribution Column）を必ず選びます。たとえば `tenant_id` や `user_id` です。
2. DDL の末尾に `SELECT create_reference_table('table_name');` または `SELECT create_distributed_table('table_name', 'shard_key');` が追加されます。

---

## 完了の確認

- [ ] 現在のデータベースの種類で「パーティショニング」または「シャーディング」が表示される。
- [ ] パーティションキーまたは分布コラムが、最もよく使う絞り込み条件や JOIN 条件と一致しており、パーティションやシャードをまたぐスキャンを避けられる。
- [ ] DDL に `PARTITION BY` 句または Citus の `create_*_table` 文が含まれている。

## 注意事項

::: warning 主キーとユニークインデックスの制約
MySQL / PostgreSQL のパーティションテーブルでは、すべての主キーとユニークインデックスのフィールドに**パーティションキーを含める必要があります**。含めない場合、テーブル作成時にデータベースがエラーを返します。
:::

- 「パーティショニング」または「シャーディング」が表示されない場合は、上部のデータベースの種類が上記のいずれかになっているか確認してください。
- パーティションはメタデータ管理の負荷を増やします。データ量が 100 万行以下の場合は、まず通常のテーブルを使ってください。
