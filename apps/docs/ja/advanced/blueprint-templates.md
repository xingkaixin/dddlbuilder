# テーブルブループリント

テーブルブループリントには、1 つのテーブルのフィールド、インデックス、データベースの種類、テーブルレベルの設定を保存します。ブループリントを適用すると、DDLBuilder はその構造を新しい下書きタブで開きます。ブループリントは現在のブラウザーに保存されます。

## 適用する場面

構造が似たテーブル（複数の注文テーブルやログテーブルなど）を繰り返し作成する場合に使います。そのうちの 1 つをブループリントとして保存しておけば、次からはブループリントから始められます。フィールドとインデックスを 1 行ずつ入力する必要はありません。

---

## ブループリントに含まれる内容

| 内容 | ブループリントを適用した後 |
|---|---|
| フィールド、インデックス | 新しい下書きにコピー |
| データベースの種類 | 新しい下書きはブループリントのデータベースの種類を使用 |
| テーブルレベルの設定（MySQL パーティション、Citus シャーディングなど） | 新しい下書きにコピー |
| テーブル名、テーブルコメント、Schema Name、被付与者 | ブループリントには保存しない。新しい下書きは現在のタブの設定を引き継ぐ |
| 外部キー | ブループリントには保存しない。適用後に設定し直す |

---

## 基本の操作手順

1. フィールド表の上にあるツールバーで **テーブルブループリント** をクリックします。
2. ブループリントの保存：
   - テーブルを編集し終えたら、**現在のテーブルをブループリントとして保存...** を選びます。
   - ブループリント名と、必要に応じて説明を入力し、**ブループリントの保存** をクリックします。
3. ブループリントの検索とプレビュー：
   - 一覧で、ブループリント名またはフィールドで検索します。
   - ブループリントをクリックするとプレビューが開きます。データベースの種類、フィールド一覧、インデックス一覧を確認できます。
4. ブループリントの適用：
   - プレビューで **ブループリントを適用する** をクリックします。
   - 構造が新しい下書きタブで開きます。元のタブの内容は変わりません。
5. 業務に合わせた調整：
   - フィールドを追加・削除し、VARCHAR の長さやデフォルト値を変更します。
   - 保存アイコンをクリックし、名前を付けて「保存済みテーブル」に保存します。
6. ブループリントの名前の変更、複製、削除は、**ブループリントを管理...** から行います。

---

## 確認と完了の目安

- [ ] ブループリントの構造が新しい下書きタブで開いている。
- [ ] フィールドの長さ、精度、デフォルト値を実際の業務に合わせて調整した。
- [ ] 生成結果の DDL が対象の方言に合っている。

## よくある注意点

::: tip 適用後は業務に合わせて調整する
ブループリントがコピーするのは、保存した時点の構造です。新しいテーブルに使う前に、業務の同時実行量、コンプライアンス要件（電話番号のマスキングや暗号化フィールドなど）、方言の特性に合わせて調整してください。
:::

- ブループリントは外部キーを保存しません。適用後に「外部キー」または「ER図」で、新しいテーブルの関連を設定してください。
- ブループリントには保存時のフィールドコメントが含まれます。別の業務に使う場合は、その業務の用語に合わせてコメントを修正してください。
