# SQL から ER 図へ：MySQL の外部キーとテーブル関係のモデリング

[DDLBuilder](https://ddl.xingkaixin.me/) を開いて、関係のモデリングを始めます。CREATE TABLE 文がすでにある場合は、先に [SQL のインポートと解析](/ja/advanced/import-and-parse)の手順でテーブル構造を読み込みます。モデリングが終わったら、[ORM モデル生成](/ja/advanced/orm-generation)に進めます。

このガイドでは、DDLBuilder の外部キーパネルと ER 図を使ってテーブル間の関係を作成し、外部キー制約を設定する方法を説明します。

## 例：ユーザーと注文の多対一の関係

この例では **MySQL の物理外部キー** を使います。1 人のユーザーは複数の注文を持つことができ、各注文は必ず 1 人のユーザーを参照します。関連付ける両側のフィールドは、どちらも符号付きの `INT` です。

### 2 つのテーブルを用意する

以下の SQL をコピーし、[DDLBuilder](https://ddl.xingkaixin.me/) で MySQL を選んで **スキーマのインポート** から取り込みます。両方のテーブルがワークスペースに保存されていることを確認してください。詳しい手順は [SQL のインポートと解析](/ja/advanced/import-and-parse)を参照してください。

```sql
CREATE TABLE users (
  id INT NOT NULL,
  name VARCHAR(100) NOT NULL,
  PRIMARY KEY (id ASC)
);

CREATE TABLE orders (
  id INT NOT NULL,
  user_id INT NOT NULL,
  PRIMARY KEY (id ASC)
);
```

### 関係を作成して ER 図を確認する

1. テーブル構成エリアで **その他** をクリックして **ER図** を開き、`orders.user_id` から `users.id` へドラッグします。
2. **物理外部キー**、**多対一**、**必須** を選び、削除時のルールを `RESTRICT`、更新時のルールを `CASCADE` にします。
3. **外部キー名** を `fk_orders_user` にし、**外部キーのインデックスを作成する** はチェックしません。**リレーションを作成** をクリックし、`orders` を保存します。

関係の向きは次のとおりです。矢印は外部キーのフィールドから、参照される主キーを指します。

```text
orders.user_id (N) ───→ users.id (1)
```

ER 図には物理外部キーを示す実線が表示されます。`users.id` は主キーです。`orders.user_id` は `NOT NULL` ですが一意制約はないため、複数の注文が同じユーザーを参照できます。

### 生成された SQL を確認する

`orders` を選ぶと、CREATE TABLE の DDL に次の内容が含まれます（書式設定によってレイアウトが変わる場合があります）。

```sql
CREATE TABLE orders (
  id INT NOT NULL,
  user_id INT NOT NULL,
  PRIMARY KEY (id ASC)
);

ALTER TABLE orders ADD CONSTRAINT fk_orders_user FOREIGN KEY (user_id) REFERENCES users (id) ON DELETE RESTRICT ON UPDATE CASCADE;
```

実際に実行するときは、先に `users` を作成し、その後で `orders` の CREATE TABLE 文と外部キー文を実行します。`RESTRICT` は、注文から参照されているユーザーの削除を防ぎます。`CASCADE` は、ユーザーの主キーが更新されたときに、注文側の参照値も更新します。MySQL のテーブルには、InnoDB など外部キーに対応したストレージエンジンを使ってください。

業務上の関連を記録するだけでよい場合は、論理リレーションを選びます。この場合、上記の `ALTER TABLE` による外部キー文は生成されません。次は [ORM モデル生成](/ja/advanced/orm-generation)で、テーブル構造がどのようにコードに対応付けられるかを確認できます。

## 論理リレーション（物理外部キーを作成しない）

物理外部キーを使わないシステムでも、テーブル間の業務上の関連を記録できます。参照元テーブルと参照先テーブルは、先にワークスペースへ保存しておく必要があります。

1. ER 図で、参照元フィールドの接続点から参照先フィールドの接続点へドラッグします。
2. ウィザードで **論理リレーション** を選び、フィールド、カーディナリティ、関係要件を確認して、業務上の説明を入力します。
3. **リレーションを作成** をクリックします。参照先フィールドに主キーや一意インデックスは必要ありません。

論理リレーションは破線で表示され、ラベルにカーディナリティと関係要件が表示されます。ラベルにカーソルを合わせると、業務上の説明を確認できます。外部キーの一覧にも「論理リレーション」と表示されます。関係は図または一覧から削除でき、一覧では関係の名前を変更できます。

論理リレーションは設計の意図を記録するだけです。物理外部キー、一意インデックス、通常のインデックスは作成せず、フィールドの NULL 許容も変更しません。DDL、ORM、ALTER/ロールバックの出力には、この関係は含まれません。関係はテーブルの保存、バージョン履歴、共有、ワークスペース同期とともに保持されます。以下で説明する物理外部キーの参照先の一意性やカスケードルールの制限は、論理リレーションには適用されません。

## 利用シーン

複数の業務テーブル（ユーザーテーブルと注文テーブル、部署テーブルと従業員テーブルなど）の間に参照関係を作成し、カスケード更新と削除のルールを設定して、ER 図でワークスペース内のすべてのテーブルの関係を確認する場面で使います。

---

## 操作手順

### 1. ER 図で関係を作成する（推奨）
1. 参照元テーブルと参照先テーブルの両方が、現在のワークスペースに保存されていることを確認します。
2. テーブル構成エリアで **その他** をクリックし、**ER図** を選びます。
3. 参照元テーブルのフィールドの左側にある接続点を、参照先テーブルのフィールドの右側にある接続点へドラッグします。
4. **テーブルリレーションの作成** ダイアログで次の項目を設定します。
   - ダイアログに入力された参照元フィールドと参照先フィールドを確認します。参照先フィールドは、単一フィールドの主キーか一意キーに限られます。
   - **カーディナリティ** で **多対一** または **1対1** を選びます。1対1 を選ぶと、ダイアログが参照元フィールドに一意インデックスを追加します。
   - **リレーションの要否** で **必須**（参照元フィールドを `NOT NULL` にする）または **任意**（参照元フィールドを `NULL` にする）を選びます。
   - **参照レコードが削除された場合** と **参照キーが更新されたとき** のルール（`NO ACTION`、`CASCADE`、`SET NULL` など）を設定し、**外部キーのインデックスを作成する** にチェックを入れるかを決めます。
5. **リレーションを作成** をクリックします。外部キー制約、フィールドの NULL 許容、インデックスがまとめて参照元テーブルに書き込まれ、ER 図に新しい関係線が表示されます。

### 2. 外部キーパネルで手動で作成する
1. 「外部キー」タブに切り替えます。
2. **外部キーの追加** をクリックします。
3. **制約名** と **参照先テーブル** を入力し、**ローカルフィールド** を選んでから、**参照先フィールド** を入力します（Enter キーで追加）。
4. 必要に応じて **削除時** と **更新時** のルールを設定します。
5. **追加** をクリックします。生成結果の DDL に `CONSTRAINT ... FOREIGN KEY ... REFERENCES ...` 文が追加されます。

### 3. ER 図を閲覧・整理する
- テーブルノードをドラッグして位置を調整するか、ツールバーの **自動レイアウト** をクリックします。
- マウスホイールでキャンバスを拡大・縮小し、キャンバスをドラッグして全体を見ます。
- 物理外部キーの関係線のラベルには、削除時と更新時のルールが表示されます。ラベルにカーソルを合わせると外部キー名を確認できます。ラベルの横にある削除ボタンをクリックすると、対応する外部キー制約が削除されます。

## 完了のチェックリスト

- [ ] 外部キーの一覧と ER 図の両方に、新しく作成した関係が表示されている。
- [ ] 生成結果の DDL に外部キー制約の文が含まれている。
- [ ] 1対1 の関係では参照元フィールドに一意インデックスがあり、結合によく使う外部キーフィールドには通常のインデックスがある。

## 注意事項

::: warning 外部キーの型の互換性と参照の条件
参照先フィールドは、単一列の主キーまたは一意インデックスの列である必要があります。参照元フィールドと参照先フィールドは、データ型と符号の有無（UNSIGNED）が一致している必要があります。一致しない場合、データベースで実行したときにエラーになります。
:::

- 削除時のルールに `SET NULL` を選ぶ場合、参照元フィールドは NULL を許可（`NULL`）する必要があり、`NOT NULL` にはできません。
- ER 図は、スキーマ名とテーブル名で参照先テーブルを探します。ワークスペースに同名のテーブルが複数ある場合、その関係線は表示されません。
