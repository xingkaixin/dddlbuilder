# CSV・Excel から INSERT SQL への変換とデータ検証

注文明細や顧客一覧など、実際の CSV / Excel データを受け取ったときは、**データベースツール** の **業務データのインポート** を開きます。新しいテーブルと INSERT SQL を生成できます。既存のテーブルに照らしてデータを検査し、INSERT SQL を生成することもできます。ログインは不要です。

業務レコードは、ブラウザーのバックグラウンドスレッドだけで処理します。アップロード、ワークスペースへの書き込み、アカウントとの同期は行いません。ツールを閉じるかアカウントを切り替えると、今回の入力と結果は消去されます。構造 SQL は引き続き既存のサービスで解析します。実際のレコードを含む INSERT スクリプトを、構造の入力元に入れないでください。

## 1. データを読み込む

`.csv`、`.tsv`、`.txt`、`.xlsx` ファイルを選ぶか、テキストを貼り付けます。CSV / テキストは UTF-8 を使います。内容に合わせて、カンマ、Tab、セミコロンのいずれかの区切り文字を選び、**データを読み込む** をクリックします。Excel ではまずワークシートが一覧表示されるので、1 つを選んで読み込みます。先頭のシートが空でも、ほかのシートを選べます。

先頭のレコードはヘッダーです。各名前は空にできず、重複もできません。CSV は、引用符内の改行と区切り文字、二重引用符によるエスケープに対応します。データ行の列数はヘッダーと同じである必要があります。すべて空のレコードはスキップします。エラーの行番号は元ファイルでの位置を示し、ヘッダーと引用符内の改行も行数に含みます。

```csv
order_code,amount,created_at
00123,19.90,2026-09-01
00124,29.50,2026-09-02
```

この例の `00123` はテキストと推定され、先頭のゼロを保持します。金額は正確な小数として扱います。

| 制限 | 上限 |
| --- | --- |
| CSV / テキスト | 2 MiB |
| xlsx 圧縮ファイル | 5 MiB。展開時のリソースも別途検査 |
| データ行 / 列 / セルの総数 | 5000 / 100 / 100000 |
| セルのテキスト | 10000 文字 |
| 読み込み後の内容の総量 | 2 Mi 文字 |

上限を超えた入力は拒否します。一部だけを切り出して読み込むことはしません。Excel の暗号化ファイル、結合セル、数式、エラーセルには対応していません。数式は、元ファイルで結果を確認してから値に変換してください。安全な精度を超える数値は、元の数字を保持したテキストセルで指定します。Excel が既に丸めた数字は復元できません。日付セルは ISO 形式に変換します。テキストの日付は、下で明示的に選んだ形式で処理します。

## 2. 対象とマッピングを確認する

### 新しいテーブルを生成する

MySQL または PostgreSQL を選び、テーブル名と、必要に応じて Schema / データベース名を入力します。ツールはすべてのレコードを走査し、整数、正確な小数、真偽値、日付、テキストのいずれかの型を推定します。内容が混在する場合はテキストを使います。フィールド名、型、NULL を許可するかどうかを編集でき、フィールドを無視することもできます。主キー、一意キー、業務上の関係は自動で推測しません。

形式のオプションを変更した後は、**現在の設定でフィールドを再推定（編集を置換）** をクリックしたときだけ、フィールド定義を再生成します。この操作は編集済みのフィールドを置き換えます。データベースを切り替えた後も、対象の型を確認し直してください。

### 既存のテーブルに照らす

MySQL / PostgreSQL の通常のテーブルを 1 つ選びます。入力元は、保存済みテーブル、構造スナップショット JSON、構造 SQL のいずれかです。ツールは選んだバージョンを使い、実際のデータベースは読みません。対象フィールドごとに元の列を 1 つ選べます。同名の列は自動で対応付けます。使われていない元の列は一覧に表示します。

**省略（デフォルト値を使用）** は、そのフィールドを INSERT から省きます。NOT NULL で既定値のないフィールドは省略できません。明示的にマッピングした空の値には、既定値を自動では使いません。フィールドの型と制約は現在選んでいる構造から取得し、マッピングのパネルでは変更できません。

### 値の扱い

- 空のセルは既定で NULL に変換します。オプションをオフにすると空文字列を保持します。文字列の `NULL` は自動で変換しません。
- 前後の空白は既定で保持します。対応するオプションにチェックを入れた場合だけ取り除きます。
- テキストの日付は ISO、DD/MM/YYYY、MM/DD/YYYY から選べます。地域ごとの形式は推測せず、存在しない日付は受け付けません。時刻は `HH:mm:ss` と最大 6 桁の小数秒を使い、フィールドの精度に合っている必要があります。
- 一般的な整数、decimal/numeric、文字型、真偽値、日付 / タイムゾーンなしのタイムスタンプ、JSON、PostgreSQL の UUID、MySQL の ENUM に対応します。未対応の型があると出力できません。浮動小数点のフィールドは浮動小数点として扱います。金額には decimal を使ってください。

## 3. 検証とダウンロード

**全データを検証して SQL を生成** をクリックすると、必須項目、型、整数の範囲、小数の精度、テキストの長さ、日付、列挙値、ファイル内での主キー / 一意キーの重複を検査します。

問題があるときは、一部だけ成功した SQL は生成しません。画面には先頭 50 件の問題と元の行番号を表示します。すべての問題と元の値を含む JSON をダウンロードできます。元ファイルかマッピングを修正してから、もう一度検証してください。入力、対象、マッピング、形式を変更すると、古い結果はすぐに消去されます。

検証を通過すると、完全な SQL をダウンロードできます。新しいテーブルのモードでは CREATE TABLE と INSERT を、既存のテーブルのモードでは INSERT だけを出力します。1 バッチは最大 100 行です。プレビューには先頭 5 行と先頭 12000 文字だけを表示しますが、ダウンロードする内容は完全です。MySQL のテキストは UTF-8 の 16 進数リテラル、PostgreSQL は E 文字列を使います。通常の文字列モードによって引用符やバックスラッシュの意味が変わるのを避けるためです。SQL は自動では実行しません。必要な Schema / データベースは事前に作成しておく必要があります。

オフラインの検証では、データベースの既存データ、外部キーの参照先、トリガー、モデル化されていない CHECK を検査しません。データベースの照合順序も再現しません。既定値を使うために省略したフィールドは、ファイル内の一意性の検査に含めません。PostgreSQL の自動採番列に値を明示して挿入した場合は、シーケンスの位置を確認してください。ファイルの検証を通過しても、どのデータベースのバージョンや設定でも実行に成功するとは限りません。

## 設定を再利用する

**インポート設定を再利用** を展開し、名前を付けて保存します。JSON のエクスポート / インポートもできます。設定に含まれるのは、対象、列のマッピング、形式のオプションだけです。業務レコード、エラーの元の値、生成した SQL は含みません。設定は現在のブラウザーに保存され、アカウントとは同期しません。最大 50 件まで保存でき、インポートするファイルは最大 256 KiB です。同名の設定を確認なしに上書きすることはありません。別の名前で保存するか、先に古い設定を削除してください。

設定を読み込む前に、今回のデータを読み込んでください。既存のテーブル用の設定では、対応するテーブルも先に選びます。マッピングは列名で復元し、列の位置では当てはめません。元の列がない、対象が違う、対象のフィールドが削除されている、のいずれかに当てはまると適用を拒否します。既存のフィールドには現在選んでいる構造の型を使い、改めて検証します。新しく追加されたフィールドは、マッピングを確認してください。読み込んだ区切り文字は、以降のファイルの読み込みに使います。

フィールド定義の一覧（「フィールド名、フィールド型、フィールドコメント」）は、引き続き [SQL のインポートと解析](/ja/advanced/import-and-parse) の構造インポートの手順を使います。
