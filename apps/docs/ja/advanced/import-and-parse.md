# CREATE TABLE 文をインポートしてテーブル構造を編集する

[DDLBuilder のモデリングワークスペース](https://ddl.xingkaixin.me/)を開き、以下の手順でインポートします。関連する複数のテーブルをインポートした後は、[外部キーと ER 図](/ja/advanced/foreign-key-and-er)で関係を確認し、[ORM モデル生成](/ja/advanced/orm-generation)でコードを出力できます。

このガイドでは、既存の SQL スクリプトやフィールド定義ファイル（CSV、Excel、JSON Schema）を、編集できるテーブル構造としてインポートする方法を説明します。

## 利用シーン

既存システムの再構築、古いプロジェクトのデータベース移行、サードパーティーの API 定義や Excel のデータ辞書からのテーブル構造の作成に使います。

---

## 操作手順

### 1. 単一または複数のテーブルの SQL をインポートする
1. ヘッダーの **スキーマのインポート** をクリックします。複数のテーブルを一度に保存する場合は、**インポートモード** を **保存済みテーブルとして保存** にします。
2. **ソースタイプ** で SQL を選び、**ソースデータベース** を選んで、SQL スクリプトを貼り付けます（`CREATE TABLE`、`CREATE INDEX`、`ALTER TABLE`、`GRANT` 文を 1 つでも複数でも指定できます）。
3. **次へ** をクリックし、構文を検証してテーブル構造を解析します。
4. 解析結果を確認して調整します。
   - ワークスペースにインポートする場合は、プレビューで解析されたフィールド、型、主キー、インデックス、権限付与の対象を確認します。フィールド名、型、NULL 許容を変更したり、フィールドを上下に移動または削除したりできます。確認したら **次へ** をクリックします。
   - **保存済みテーブルとして保存** を選んだ場合、フィールドのプレビューはありません。インポートするテーブルにチェックを入れて **次へ** をクリックし、**対象フォルダー** と **同名競合の処理** を選びます。選択肢は **既存をスキップする**、**既存のものを上書きする**、**自動名前変更** です。
5. **インポート** をクリックします。SQL にスキーマの接頭辞がある場合（例: `CREATE TABLE sales.orders`）、`sales` は `スキーマ名` に、`orders` は `テーブル名` に入ります。

### 2. フィールド定義ファイルをインポートする（CSV / Excel / JSON Schema）

実際の注文や顧客一覧などの業務レコードには、[業務データのインポート](/ja/advanced/business-data-import)を使ってください。このページの CSV / Excel のインポートは、フィールド定義の一覧を扱います。

1. ヘッダーの **スキーマのインポート** をクリックし、**ソースタイプ** で次のいずれかを選びます。
   - **CSV / TSV**：1 行目は見出し（フィールド名、フィールドの型、フィールドのコメント）です。2 行目以降は 1 行に 1 フィールドを記述します。
   - **Excel**（.xlsx / .xls）：ワークシートごとに 1 つのテーブルとしてインポートし、シート名をテーブル名にします。1 行目は見出し（フィールド名、フィールドの型、フィールドのコメント）で、2 行目以降は 1 行に 1 フィールドです。
   - **JSON Schema / OpenAPI**：`properties` にあるフィールドと、その型、フォーマット、説明を読み込みます。
2. ファイルをアップロードして **次へ** をクリックし、プレビューでフィールドと型を確認して、必要に応じて修正します。
3. **インポート** をクリックすると、フィールドが現在のワークスペースに書き込まれます。

## 対応する構文とファイルの仕様

| 形式 / ソース | 対応する構文とファイルの条件 | 解析の動作 |
|---|---|---|
| **SQL スクリプト** | `CREATE TABLE`、`CREATE INDEX`、`ALTER TABLE`、`GRANT` | 列制約、デフォルト値、コメント、複合インデックス、権限付与を抽出する |
| **CSV ファイル** | UTF-8 エンコード、半角カンマ区切り、1 行目は見出し | フィールド名、明示された SQL 型、コメントを読み込む |
| **Excel ファイル** | `.xlsx`、`.xls` 形式に対応 | 各ワークシートのフィールド定義一覧を読み込む |
| **JSON Schema** | JSON Schema、Swagger、OpenAPI のドキュメント | `properties` を抽出し、`type` と `format` からフィールドの型を決める。`object` と `array` は `json` にする |

## 完了のチェックリスト

- [ ] 解析されたテーブル名、フィールド、制約、インデックスがワークスペースに表示されている。
- [ ] 元の SQL にスキーマの接頭辞がある場合、`スキーマ名` と `テーブル名` にそれぞれ値が入っている。
- [ ] 生成結果の DDL と DCL が、対象データベースの構文に合っている。

## 注意事項とトラブルシューティング

::: tip 方言の不一致を確認する
インポート時に構文エラーが表示される場合は、まずインポートダイアログの **ソースデータベース** が SQL の実際の構文と合っているかを確認してください。例えば、Oracle の構文なのに MySQL を選んでいる場合です。
:::

- 1 回でインポートできる SQL は最大 50,000 文字です。超える場合は、業務モジュールごとに分けてインポートしてください。
- CSV ファイルは UTF-8 で保存してください。Excel ファイルは、パスワード保護を解除してからアップロードしてください。
- JSON Schema 内でネストした `object` と `array` のプロパティは、1 つの `json` フィールドとしてインポートされます。複数のテーブルに分ける場合は、先に JSON Schema でエンティティを分けてからインポートしてください。
