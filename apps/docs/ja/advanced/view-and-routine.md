# ビューと Routine の設定

このガイドでは、DDLBuilder での**ビュー（CREATE VIEW）**の定義および**ストアドプロシージャ（Procedure）**、**関数（Function）**、**トリガー（Trigger）**の標準コード雛形の生成手順を解説します。

## 概要

基本の物理テーブルに加えて、ビューによるデータ抽象レイヤーや、データベース側で動作するプロシージャ・トリガーの初期骨格コードを一元的に設計・出力できます。

---

## 主な操作手順

### 1. ビュー（View）の定義と DDL 出力
1. 設定エリア内の**「ビュー定義」**パネルを開きます。
2. **ビュー名**（例: `v_user_order_summary`）と標準的な **SELECT クエリ文**を入力します。
3. 外部公開用のカラム名を指定したい場合は、SELECT 文中で `AS` による明示的な別名定義を行います。
4. 右側の出力エリアで**「ビュー/Routine」**タブに切り替えると、対象方言に準拠した `CREATE VIEW ... AS SELECT ...` 文が自動生成されます。
5. **「ビュー DDL をコピー」**をクリックして利用します。

### 2. Routine（プロシージャ/関数/トリガー）の雛形生成
1. 「その他設定」または設定パネル内の **Routine テンプレート**セレクターを開きます。
2. 生成したいオブジェクトタイプを選択します。
   - **ストアドプロシージャ（Stored Procedure）**: 入出力パラメーター（`IN` / `OUT`）とトランザクションブロックの骨格を生成します。
   - **ユーザー定義関数（Function）**: 戻り値の型宣言と処理本体を含む雛形を出力します。
   - **トリガー（Trigger）**: 起動タイミング（`BEFORE` / `AFTER`）と対象イベント（`INSERT` / `UPDATE` / `DELETE`）を設定し、構文ヘッダーを出力します。
3. 右側出力エリアの **Routine** ビューで**「Routine をコピー」**をクリックし、データベースクライアントで業務ロジックを実装します。

---

## 完了のチェックリスト

- [ ] ビュー DDL が対象データベースの構文規則に完全に合致している。
- [ ] ビューの SELECT クエリ内で参照されているテーブルとカラム名が正確である。
- [ ] Routine の骨格コードをコピーし、DB クライアントで問題なくコンパイルできる。

## 注意事項

::: tip 業務ロジックの実装
Routine テンプレートが出力するのは構文的な骨格とシグネチャです。内部の計算処理や条件分岐は業務要件に合わせて手動で実装してください。
:::

- **ビューの依存順序**: ビューが参照する物理テーブルが作成される前にビューを実行するとエラーになるため、デプロイ順序にご注意ください。
- **方言による構文差異**: プロシージャとトリガーの構文は Oracle（PL/SQL）、PostgreSQL（PL/pgSQL）、SQL Server（T-SQL）間で大きく異なります。方言を切り替えた際は必ず構文を確認してください。
