# 設定の表示と定期的な設定

## これは誰に向けたものですか

テーブル作成ステートメントに加えて、ビュー DDL またはストアド プロシージャ、関数、およびトリガーのスケルトン コードを生成する必要があるユーザー向け。

## これで解決すること

テーブル、ビュー、および日常的なスケルトン設計を同じツールで完了できるため、複数のツール間で切り替えるコストが削減されます。

## 前提条件

- 作成するビュークエリまたはルーチンタイプはすでに特定されています。
- 現在のデータベース タイプは、対応する構文をサポートしています (ほとんどのデータベースはビューをサポートしています。ルーチンのサポートはデータベースによって異なります)。

## ステップ

### 構成の表示

1. テーブル構成領域 (通常はテーブル構成の下、または独立したタブ) で `View Definition` パネルを見つけます。結果: ビュー エディターが開きます。
2. `View Name` および `SELECT` クエリを入力します。結果: システムはビュー定義を保存します。
3. フィールド エイリアスの場合、SELECT で明示的に `AS` を使用します。結果: 生成された `CREATE VIEW` 列リストにエイリアスが表示されます。
4. 右側の出力領域の `View` タブに切り替えます。結果: システムは、対応するデータベースの `CREATE VIEW` ステートメントを生成します。
5. 「`Copy View DDL`」をクリックします。結果: ステートメントがクリップボードにコピーされます。

### ルーチンテンプレート

1. テーブル構成領域で `Routine Templates` または `Misc Settings` を見つけます。結果: テンプレート セレクターが開きます。
2. タイプを選択します: `Stored Procedure`、`Function`、または `Trigger`。結果: システムは、対応するスケルトン テンプレートをロードします。
3. 必要に応じて、テンプレート内のパラメータ名、戻り値の型、またはトリガーのタイミングを調整します。結果: テンプレートのパーソナライズが完了しました。
4. 右側の出力領域の `Routine` タブに切り替えます。結果: システムは完全な `CREATE PROCEDURE` / `CREATE FUNCTION` / `CREATE TRIGGER` スケルトンを生成します。
5. 「`Copy Routine`」をクリックします。結果: コードがクリップボードにコピーされ、データベース クライアントにビジネス ロジックを入力し続ける準備が整います。

## いつ完了するか

- DDL またはルーチン コードが正常にコピーされたことを表示します。
- 構文がターゲット データベースの言語と一致する。
- ビュー クエリはターゲット データベース上で正しく実行できます (データベース クライアントでの 2 番目の検証を推奨します)。

## よくある落とし穴

- ビュー内の SELECT クエリが存在しないテーブルまたはフィールドを参照している場合、生成された DDL は構文的には正しいですが、実行時に失敗します。
- トリガー `BEFORE` / `AFTER` と `INSERT` / `UPDATE` / `DELETE` の組み合わせは、ターゲット データベースのサポートされている範囲と一致する必要があります。
- ルーチン テンプレートはスケルトン コードのみを生成します。ビジネス ロジックには手動による補足が必要です。
- ルーチン構文はデータベースによって大きく異なります (例: Oracle PL/SQL と SQL Server T-SQL)。データベースの種類を切り替えた後、生成された結果を再確認してください。
