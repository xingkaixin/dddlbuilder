# ビューと Routine の設定

このページでは、DDLBuilder でビュー（`CREATE VIEW`）を定義する方法と、ストアドプロシージャ、関数、トリガーのコードテンプレートを生成する方法を説明します。

## 利用場面

通常のテーブルに加えてビューも管理したい場合や、ストアドプロシージャ、関数、トリガーの土台となるコードが必要な場合に使います。

---

## 操作手順

### 1. ビューの定義と DDL の生成
1. テーブル設定エリアで **プロパティ** をクリックし、**オブジェクトの種類** を **ビュー** に変更します。
2. **ビュー名**（例: `v_user_order_summary`）を入力します。
3. **ビュー SQL** タブの **クエリSQL** に SELECT 文を入力します。外部に公開する列名を指定する場合は、SELECT の中で `AS` を使って別名を宣言します。
4. **CREATE OR REPLACE** はデフォルトでオンになっており、`CREATE OR REPLACE VIEW`（SQL Server では `CREATE OR ALTER VIEW`）を生成します。オフにすると `CREATE VIEW` を生成します。SQLite / D1 では常に `CREATE VIEW` を生成します。
5. 生成結果の **DDL** タブに `CREATE VIEW ... AS SELECT ...` 文が生成されます。**DDLのコピー** をクリックするとコピーできます。

### 2. Routine（ストアドプロシージャ、関数、トリガー）のテンプレート
1. 生成結果で **ルーチン** タブをクリックします。SQLite / D1 ではこのタブはありません。
2. **テンプレート** で生成するオブジェクトを選びます。
   - **自動更新タイムスタンプトリガー** は、レコードを更新したときに、指定した更新時刻のフィールドを現在時刻に設定します。
   - **監査ログトリガー** は、データが変更された後に、監査テーブルへ 1 行を書き込みます。
   - **ストアドプロシージャ** では、パラメータ（例: `IN p_user_id INT`）と本体を入力します。
   - **関数** では、パラメータ、戻り値の型、本体を入力します。
   - **カスタムトリガー** では、トリガーテーブルと本体を入力します。`BEFORE INSERT` トリガー（SQL Server では `AFTER INSERT`）が生成されます。
3. **ルーチンをコピー** をクリックしてコードをコピーし、データベースクライアントで業務ロジックを補います。

---

## 完了の確認

- [ ] ビューの DDL が対象データベースの構文に合っている。
- [ ] ビューのクエリで参照しているテーブル名とフィールド名が正しい。
- [ ] ルーチンのコードがデータベースでコンパイルを通った。

## 注意事項

::: tip 業務ロジックを補う
ルーチンのテンプレートが生成するのは文の構造だけです。ストアドプロシージャ、関数、カスタムトリガーの本体は、業務に合わせて自分で書く必要があります。
:::

- ビューのクエリが参照するテーブルやフィールドが存在しない場合、ビューの DDL を実行するとエラーになります。先にビューが依存するテーブルを作成してください。
- ストアドプロシージャとトリガーの構文は、Oracle（PL/SQL）、PostgreSQL（PL/pgSQL）、SQL Server（T-SQL）の間で大きく異なります。テンプレートは現在のデータベースの種類に合わせて生成されますが、入力した本体は変換されません。データベースの種類を切り替えた後は、改めて確認してください。
