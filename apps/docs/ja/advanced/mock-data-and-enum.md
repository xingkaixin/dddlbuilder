# Mock データと論理列挙

このガイドでは、DDLBuilder での高品質な **Mock 検証用データ生成**、およびカラムへのカラーバッジ付き**論理列挙型（Logical Enum）**メタデータの設定手順を解説します。

## 概要

開発・テスト段階でのクエリ動作検証用データを即座に生成するとともに、ステータスコードや区分フラグの取り得る値を視覚的に定義し、仕様の認識齟齬を防ぎます。

---

## 主な操作手順

### 1. Mock テストデータの生成とエクスポート
1. テーブルにカラム名とデータ型が設定されていることを確認します。
2. ツールバーの **「Mock データ」** ボタンをクリックして生成パネルを開きます。
3. **生成パラメーターの指定**:
   - 生成行数を指定します（1〜100 行）。
   - プレビューを確認します。整数、小数、UUID、日時、メールアドレス、真偽値などのデータ型に応じたランダムサンプルが自動生成されます。
4. **データのエクスポート**:
   - 出力形式を選択します: **SQL INSERT 文**、**CSV ファイル**、**JSON 配列**。
   - コピーまたはエクスポートを実行し、ローカル検証用 DB や Postman 等に投入して利用します。

### 2. カラムへの論理列挙型（Logical Enum）設定
ステータスコード、審査状態、ユーザー種別などの離散値を持つカラムに対して:
1. 「フィールド設定」テーブルで対象カラムの行内**列挙型エディター**を展開します。
2. 「列挙項目を追加」をクリックし、**列挙値**（例: `10`、`PAID`）と**表示名**（例: `決済完了`）を入力します。
3. **カラーバッジの割り当て**: 各項目に識別用カラー（成功は緑、拒否は赤、処理中は黄など）を設定し、状態を一目で判別できるようにします。
4. **ドラッグ並べ替え**: 左側のハンドルで項目をドラッグし、業務上の表示順序を調整します。
5. 列挙型メタデータは下書きや保存済みテーブルと共に保存され、チーム開発時のデータ辞書として機能します。

## 完了のチェックリスト

- [ ] Mock データが指定形式で正常に出力され、テスト DB に投入可能である。
- [ ] 論理列挙型がすべての業務分岐状態を網羅し、色分けされている。
- [ ] テーブルを再読み込みした後も列挙型の設定が維持されている。

## 注意事項

::: tip 個人情報と合成データの安全性
Mock データエンジンが生成するのは完全な合成ランダムデータです。本番の実データを無断で開発環境にコピーせず、安全なモックデータをご活用ください。
:::

- **外部キー制約の考慮**: モックデータは単一テーブルの型情報に基づいて生成されるため、他テーブルへの外部キー依存関係は考慮されません。投入順序にご注意ください。
- **物理 ENUM と論理列挙の違い**: 論理列挙型は画面表示と仕様共有のためのメタデータです。データベース自体の物理制約として `ENUM` 型を利用したい場合は、データ型で各方言の `ENUM` を選択してください。
