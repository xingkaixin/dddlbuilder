# モックデータと論理列挙型

## これは誰に向けたものですか

テストデータを素早く生成する必要がある場合や、フィールド値の仕様を視覚的に統一したい場合。

## これで解決すること

モック データは、開発およびテスト中に構造に準拠したデータを迅速に入力するのに役立ちます。論理列挙型によりフィールド値の仕様が可視化され、チームでのコラボレーション中の理解の逸脱が軽減されます。

## 前提条件

- 現在のテーブルはフィールド構成が完了しています。
- モックデータの生成には、明確なターゲット行数とエクスポート形式が必要です。

## ステップ

### モックデータの生成

1. テーブル構成領域またはフィールド構成ツールバーで `Mock Data` をクリックします。結果: [モック データ生成] ダイアログが開きます。
2. ターゲット行数を設定します (例: 100、1000)。結果: システムは、フィールド タイプごとに対応するランダム データを生成します。
3. 生成プレビューを確認し、文字列の長さ、数値範囲、および日付形式が期待どおりであることを確認します。結果: 偏差が大きい場合は、フィールド設定に戻ってデフォルトまたはタイプを調整し、再生成します。
4. エクスポート形式 (SQL INSERT、CSV、JSON など) を選択します。結果: データがバッチでエクスポートされ、テスト データベースにインポートしたり、テスト仲間に渡したりできるようになります。

### 論理列挙型構成

1. フィールド構成テーブルでターゲット フィールドを見つけ、`Enum` エディターを展開します。結果: enum 項目管理パネルが表示されます。
2. `Add Enum Item` をクリックし、列挙値と表示名を入力します。結果: enum リストに項目が 1 つ追加されます。
3. 列挙項目の色の識別子を選択します。結果: 異なる列挙値は、インターフェイス上で異なる色で区別され、簡単に識別できるようになります。
4. 列挙項目をドラッグして順序を調整します。結果: 注文はドラフトと保存されたテーブルに保持されます。
5. フィールドのコメントを入力するときに、フィールドの列挙型の仕様に注意してください。結果: チームのコラボレーションが価値の意味を理解しやすくなります。

## いつ完了するか

- モックデータは正しい形式でエクスポートされており、テストの準備ができています。
- 列挙型アイテムは、直感的な色の識別子を使用して、すべての有効なビジネス値をカバーします。
- 列挙型メタデータはテーブルとともに保存され、リロード後も有効なままです。

## よくある落とし穴

- モックデータはランダムに生成され、実際のビジネス分布を表すものではありません。機密フィールド (電話番号、ID など) については、マスキング ルールを使用した二次処理をお勧めします。
- enum 値が変更された後、以前に生成されたモック データは自動的に更新されません。再生が必要です。
- すべてのデータベース タイプが列挙型をネイティブにサポートしているわけではありません。システムは、DDL のコメントまたは制約を介して enum 仕様を表現します。実際の効果はターゲット データベースに応じて異なります。
- Enum カラーはインターフェイス表示専用であり、DDL には書き込まれません。
