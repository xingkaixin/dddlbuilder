# クイックスタート

このガイドでは、初めて DDLBuilder を利用するユーザー向けに、数分で最初のテーブル構造を設計し、高品質な建表 SQL や ORM コードを生成・取得する手順を解説します。

## 概要

データベースごとの方言に合わせた SQL の手書き作業から解放されます。視覚的な Web インターフェースを通じて、テーブル設計、制約設定、インデックス定義を行い、精度の高い建表 DDL、権限 DCL、ORM モデルコード、ビュー/Routine の雛形をリアルタイムに生成できます。

## 操作手順

### 1. データベース方言と基本情報の設定
- テーブル設定ヘッダーで対象の**データベースタイプ**（MySQL、PostgreSQL、Oracle、TiDB など）を選択します。
- **テーブル名**（例: `user_account`）と**表示名（日本語名）**（例: `ユーザーアカウント表`）を入力します。
- **Schema Name**（任意）: スキーマ/名前空間をサポートするデータベース（PostgreSQL、Oracle、SQL Server など）では、スキーマ名を入力すると `schema.table` の修飾名形式で SQL が自動生成されます。

::: tip テーブル名の入力ルール
`テーブル名` 入力欄には純粋なテーブル名のみを入力してください。スキーマを指定する場合は、専用の `Schema Name` 欄を使用し、テーブル名欄に直接 `schema.table` と入力しないようにしてください。
:::

### 2. フィールド（カラム）と制約の定義
- 「フィールド設定」テーブルで、**フィールド名**、**日本語名**、**データ型**を1行ずつ追加・編集します。
- 業務要件に応じて、**NULL 許容**（`NOT NULL` / `NULL`）、**デフォルト型**（定数、現在時刻、UUID など）、**デフォルト値**を設定します。
- 右側の「建表 DDL」出力パネルがリアルタイムに更新され、対象方言に準拠した SQL がプレビューされます。

### 3. インデックス、権限、詳細オプションの設定
- **インデックス設定**: 主キー、一意制約（ユニークインデックス）、複合クエリインデックスをすばやく追加し、検索性能を担保します。
- **権限設定**: 権限を付与するユーザーやロール名を入力し、対応する `GRANT` 文（DCL）を自動生成します。
- **外部キー・その他設定**: 必要に応じて、ストレージエンジン、文字コード、照合順序、テーブルスペースなどを設定します。

### 4. テーブルブループリント（テンプレート）の活用（任意）
標準的な業務テーブル（ユーザー、注文、ログなど）を作成する場合は、上部ツールバーの**表ブループリント**からテンプレートを選択してワンクリックで適用し、必要に応じてカスタマイズできます。

### 5. 既存構造のリバースインポート（任意）
既存の SQL スクリプトやデータファイルがある場合は、上部の**SQL インポート**または**データインポート**（CSV、Excel、JSON Schema）をクリックすると、フィールドや型、インデックスが自動解析されて反映されます。

### 6. コードのコピーとエクスポート
- 右側の出力エリアで**DDL コピー**または**DCL コピー**をクリックし、SQL をクリップボードにコピーして利用します。
- **ORM** タブに切り替えると、Prisma、TypeORM、SQLAlchemy、GORM、JPA などのモデル定義コードをエクスポートできます。
- **ビュー/Routine** タブでは、ビュー定義やストアドプロシージャ、関数、トリガーのコード雛形を取得できます。

### 7. 保存とマルチタブ管理
- テーブル名の横にある**保存アイコン**をクリックして名前を付けて保存すると、「保存済みテーブル」ドロワーからいつでも再読み込みできます。
- ワークスペースは**複数タブ**の並行編集に対応しており、各テーブルを独立して安全に管理できます。

---

## 完了の確認

- [ ] 右側の出力エリアに、構文エラーのない完全な `CREATE TABLE` 文が表示されている。
- [ ] `Schema Name` を設定した場合、DDL/DCL にスキーマ修飾テーブル名が反映されている。
- [ ] コピーボタンを押した際に「コピー完了」の通知が表示される。
- [ ] 「保存済みテーブル」一覧に保存したテーブルが表示されている。

## 注意事項

::: warning データベース方言の切り替え
設計の途中でデータベースタイプを変更すると、データ型のマッピングや構文ルールが新しい方言に合わせて再計算されます。作業開始時に対象データベースを確定しておくことをお勧めします。
:::

- **ログインとクラウド同期**: 未ログイン時は現在のブラウザローカルストレージにのみ保存されます。右上のアカウントからログインすると、複数デバイス間でリアルタイムに自動増分同期されます。
- **未保存の変更**: 未保存の変更があるタブを閉じる際には保存確認ダイアログが表示され、作業内容の誤消失を防ぎます。
