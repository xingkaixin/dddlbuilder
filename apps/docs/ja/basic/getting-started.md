# MySQL・PostgreSQL の CREATE TABLE 文をオンラインで生成

[DDLBuilder で設計を始め](https://ddl.xingkaixin.me/)、以下の手順で最初のテーブルを作成します。SQL がすでにある場合は、[SQL のインポートと解析](/ja/advanced/import-and-parse)を使えます。

## 例：MySQL のユーザーテーブルを生成する

ユーザーテーブルを作成します。`id` は主キー、`email` は必須かつ一意、`display_name` は空でもかまいません。次の SQL はそのまま取り込みの例として使えます。

```sql
CREATE TABLE user_account (
  id INT NOT NULL,
  email VARCHAR(255) NOT NULL,
  display_name VARCHAR(100),
  PRIMARY KEY (id)
);
CREATE UNIQUE INDEX uk_user_account_email ON user_account (email);
```

1. [DDLBuilder](https://ddl.xingkaixin.me/) を開き、上部の「スキーマのインポート」をクリックします。「ソースタイプ」で SQL、「ソースデータベース」で MySQL を選び、例を貼り付けます。
2. プレビューに 3 つのフィールド、`id` の主キー、`email` の一意インデックスがあることを確認してから、テーブル構造を取り込みます。
3. `display_name` の長さを `150` に変更します。「生成結果」の「DDL」タブで `VARCHAR(150)` になったことを確認してから、SQL をコピーします。

出力後の整形、識別子の引用符、インデックス文の位置は異なる場合があります。フィールドの型、NULL 許容、主キー、一意インデックスの意味を確認してください。対象データベースを切り替えた後も、型とデフォルト値の互換性を確認する必要があります。DDLBuilder がデータベースに接続して SQL を実行することはありません。

複数テーブルのリレーションが必要な場合は [SQL から ER 図](/ja/advanced/foreign-key-and-er)、アプリケーションのコードが必要な場合は [SQL から ORM モデル](/ja/advanced/orm-generation)に進んでください。

## 利用場面

画面でテーブル構造を設定すると、DDLBuilder は選択したデータベースに合わせて、CREATE TABLE の DDL、権限付与の DCL、ORM モデルコード、ビューとルーチンの SQL をその場で生成します。データベースごとに SQL を手書きする必要はありません。

## 基本の操作手順

### 1. データベースの種類と基本情報を設定する
- テーブル設定エリアで「データベースの種類」を選びます（MySQL、PostgreSQL、Oracle、TiDB など）。
- 「テーブル名」（例：`user_account`）と「テーブルコメント」（例：`ユーザーアカウント表`）を入力します。
- 名前空間をサポートするデータベース（PostgreSQL、Oracle、SQL Server など）では、「プロパティ」で「スキーマ名」を入力できます（任意）。生成される SQL のテーブル名は `schema.table` の形式になります。

::: tip テーブル名の入力ルール
「テーブル名」にはテーブル名だけを入力します。名前空間が必要な場合は「スキーマ名」に入力し、テーブル名に `schema.table` と書かないでください。
:::

### 2. フィールドと制約を設定する
- 「フィールド」の表で、行ごとに「フィールド名」「コメント」「タイプ」を入力します。
- 必要に応じて「NULL 許容」（`NOT NULL` / `NULL`）、「デフォルトの種類」（定数、現在の時刻、UUID など）、「デフォルト値」を設定します。
- 「生成結果」の「DDL」タブは、入力に合わせてその場で更新されます。

### 3. インデックス、権限、詳細設定を追加する
- 「インデックス」タブで、主キー、一意インデックス、通常のインデックスを追加します。1 つのインデックスに複数のフィールドを含められます。
- 「権限」タブでユーザーまたはロールを追加すると、`GRANT` 文（DCL）が生成されます。
- 「その他」タブで、ストレージエンジン、文字セット、照合順序、テーブルスペースを設定します。

### 4. テーブルブループリントを適用する（任意）
テーブルブループリントは、自分で保存したテーブル構造です。DDLBuilder に組み込みのブループリントはありません。「フィールド」のツールバーで「テーブルブループリント」をクリックし、ブループリントを選んで「ブループリントを適用する」をクリックします。DDLBuilder は新しい下書きのタブを開き、ブループリントのフィールド、インデックス、データベースの種類、テーブルレベルの設定を読み込みます。新しいタブには、現在のテーブルのテーブル名、表のコメント、スキーマ名、被付与者が引き継がれます。外部キーは含まれません。

ブループリントがまだない場合は、同じメニューで「現在のテーブルをブループリントとして保存...」を選びます。ブループリントは現在のブラウザに保存されます。

### 5. 既存の構造を取り込む（任意）
SQL やテーブル構造のファイルがすでにある場合は、上部の「スキーマのインポート」をクリックします。「ソースタイプ」では SQL、CSV / TSV、Excel、JSON Schema / OpenAPI を選べます。DDLBuilder はフィールド、型、インデックスを解析し、ワークスペースに読み込みます。

### 6. 出力をコピー・エクスポートする
- 「生成結果」で「DDLのコピー」または「DCL のコピー」をクリックし、データベースクライアントやチケットシステムに貼り付けます。
- 「ORM」タブに切り替えると、Prisma、TypeORM、SQLAlchemy、GORM、JPA のモデルコードを生成できます。
- 「ルーチン」タブに切り替えると、ストアドプロシージャ、関数、トリガーのコードの雛形を生成できます。オブジェクトの種類がビューの場合、`CREATE VIEW` 文は「DDL」タブに表示されます。

### 7. 保存と複数タブの管理
- テーブル設定エリアの保存アイコン（ツールチップは「現在のテーブルを保存する」）をクリックし、名前を付けます。保存したテーブルは、左側の「ワークスペース」サイドバーの「プロジェクト」に表示されます。以後はここから開けます。テーブル設定エリアで「バージョン履歴」を確認することもできます。
- ワークスペースでは複数のタブを同時に開けます。1 つのタブで 1 つのテーブルを編集します。

## ユーザー登録とメール認証（任意）

ローカルでのモデリングにサインインは不要です。アカウントのワークスペースを同期する場合は、右上から登録画面を開き、メールアドレスとパスワードを入力します。

1. 登録後、メールに記載された 6 桁の認証コードを認証ダイアログに入力するか、貼り付けます。
2. 認証コードの有効期限は 10 分です。認証に成功すると自動的にサインインします。
3. メールが届かない場合は、まず迷惑メールフォルダーを確認してください。60 秒の再送信カウントダウンが終わると再送信できます。最新の認証コードを使ってください。

登録に CAPTCHA は不要です。既存のアカウントでメールアドレスが未認証と表示される場合も、認証ダイアログで認証できます。詳しい対処方法は[サインインとワークスペース同期の問題](/ja/faq/common-errors#sign-in-and-sync)を参照してください。

## 確認チェックリスト

- [ ] 「DDL」タブに完全な `CREATE TABLE` 文があり、対象データベースの構文に合っている。
- [ ] 「スキーマ名」を入力した場合、DDL と DCL のテーブル名にスキーマの接頭辞が付いている。
- [ ] コピーボタンをクリックすると「コピーされました」と表示される。
- [ ] 左側の「ワークスペース」サイドバーの「プロジェクト」に、保存したテーブルが表示されている。

## 注意事項

::: warning データベースの種類を合わせる
途中でデータベースの種類を切り替えると、フィールドの型のマッピングと構文ルールが新しいデータベースに合わせて調整されます。設計を始める前に、対象のデータベースの種類を決めておくことをおすすめします。
:::

- サインインしていない場合、データは現在のブラウザにのみ保存されます。右上の「サインイン」からサインインすると、ワークスペースは自動でクラウドに同期されます。他のデバイスで同じアカウントにサインインすれば、編集を続けられます。
- タブを閉じても確認ダイアログは表示されません。編集中の内容は自動で下書きとして保存され、保存済みテーブルは上書きされません。
