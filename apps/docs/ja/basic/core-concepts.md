# コアコンセプト

## これは誰に向けたものですか

すでに UI をクリックして操作することはできますが、「ドラフト ボックス」、「保存されたテーブル」、「共有コピー」、「DDL/DCL」、および新しいマルチタブ ワークスペースについては十分に理解していないユーザー向けです。

## これで解決すること

これらの概念を理解すると、現在の変更がどこに保存されるか、他のユーザーが共有コンテンツを編集できるかどうか、どの SQL ブロックをコピーする必要があるか、およびマルチタブ ワークスペースがどのように動作するかを知ることができます。

## ステップ

1. まず「ワークスペース」の概念を確認します。現在の構成全体が 1 つのワークスペースにあり、複数のタブがサポートされます。各タブは 1 つのテーブルを独立して管理します。結果: タブ内の現在の入力はすべてそのタブのテーブル デザインに属しており、タブを切り替えても相互に影響を及ぼさないことがわかります。
2. 「ドラフト ボックス」を理解します。保存されている特定のテーブルがロードされていない場合は、ドラフト ボックスに入ります。ドラフト ボックスは、左側のワークスペース サイドバーで管理される複数の名前付きドラフトをサポートします。結果: 一時デザインはデフォルトでドラフト ボックスに移動し、保存されたテーブルは上書きされません。複数のドラフトを共存させ、必要に応じて切り替えることができます。
3. 「保存されたテーブル」を理解します。手動で保存すると、繰り返しロードできる名前付きスナップショットが取得されます。保存されたテーブルはソフト削除をサポートしており、削除後にゴミ箱に移動します。復元または永久に空にするオプションがあります。結果: 安定したバージョンと一時的なドラフトを個別に管理できるようになり、誤って削除した場合に回復期間が設けられます。
4. 「共有コピー (読み取り専用)」を理解します。共有リンクによって開かれたページは、デフォルトでは直接編集できません。結果: 変更を加える前に、[コピーとして保存して編集] をクリックする必要があることがわかります。
5. 「DDL / DCL」を理解する: DDL はテーブル作成 SQL、DCL は特権 SQL です。結果: シナリオごとに正しい出力をコピーし、それらの混合を回避できます。
6. 「ORM / ビュー / ルーチン」を理解する: ORM はターゲット フレームワーク用に生成されたモデル コードです。ビューは CREATE VIEW ステートメントです。ルーチンは、ストアド プロシージャ、関数、トリガーのスケルトン コードです。結果: 配信ターゲットに基づいて出力タイプを選択できます。
7. 「ユーザー アカウントとワークスペースの同期」を理解します。サインイン後、データはアカウントにバインドされます。下書き、保存されたテーブル、フォルダー、ゴミ箱は段階的に同期されますが、設定には回復ツールとして「今すぐ同期」、「クラウドへのアップロード」、「クラウドからダウンロード」が引き続き提供されます。結果: デバイスを切り替えるときは、最初にサインインしてから自動同期を待つか、手動同期をトリガーする必要があることがわかります。
8. 「AI クレジット」を理解する: AI テーブルの生成、AI による現在のテーブルの変更、AI インデックス アドバイザー、DDL レビュー、SQL の説明、および AI コメントの生成は、実際のトークン使用量に基づいてクレジットを消費します。結果: AI 機能を引き続き使用するには十分なクレジットが必要であり、AI を使用するには匿名ユーザーが最初にサインインする必要があることがわかります。
9. 「ゴミ箱」について理解します。削除された保存済みテーブルはすぐには消えませんが、保持期間の間ゴミ箱に入れられます。結果: 誤って削除したテーブルをゴミ箱から復元できます。ゴミ箱を一括で空にすることを最初に確認する必要があります。

## いつ完了するか

- 現在がドラフト ボックスにいるのか、保存されたテーブルにいるのかが明確にわかります。
- マルチタブ モードのテーブルは独立しているため、タブを切り替えても未保存のコンテンツは失われません (ただし、タブを閉じるとプロンプトが表示されます)。
- 共有ページは直接編集できないため、最初にコピーに変換する必要があることがわかります。
- 構造の変更は DDL にあり、権限の付与は DCL にあり、ビジネス モデルは ORM に基づいていることがわかります。
- サインイン後にワークスペースが自動的に同期され、設定で手動の同期または回復アクションを実行できることを知っています。
- AI 機能にはクレジットが必要で、サインインしないと利用できないことはご存知でしょう。
- 削除された保存テーブルはゴミ箱から復元できることはご存知でしょう。

## よくある落とし穴

- 「ドラフト ボックスの自動保存」を「保存されたテーブル」と間違えると、後で名前付きバージョンが欠落しているように見える可能性があります。
- 共有ビューは読み取り専用であるため、共有ページで直接編集しても効果はありません。
- DCL ではなく DDL のみを確認すると、権限の付与が失われる可能性があります。
- AI 機能は、匿名の場合にサインインするように要求し、サインイン後にクレジットが不足している場合は制限されます。
- デバイス間で同じワークスペースを編集すると、設定に同期の競合通知が表示される場合があります。まず競合項目を検査してから、ワークスペース全体を上書きするために手動アップロードまたはダウンロードのどちらを使用するかを決定します。
- サインインせずにブラウザーのデータをクリアすると、ローカルの下書きと保存されたテーブルが消去されます。重要なデータは、サインイン後にクラウドに同期する必要があります。
- 変更が保存されていないタブを保存せずに閉じると、それらの変更は失われます (下書きの自動保存は現在アクティブなタブにのみ適用されます)。
