# DDL 出力と共有

## これは誰に向けたものですか

スキーマの構成が完了し、外部レビュー、コラボレーションの確認、または SQL 配信の準備をしているユーザー向け。

## これで解決すること

何をコピーするか、共有後に他の人ができることを明確にし、間違ったコンテンツの受け渡しや、共有ページが直接編集可能であるという思い込みを避けることができます。

## ステップ

1. 右側の出力領域で、まず `Table DDL` を確認します。結果: `CREATE TABLE` が予想した構造と一致するかどうかを確認できます。 `Schema Name` が設定されている場合、出力ではスキーマ修飾されたテーブル名が使用されます。
2. `Privilege DCL` に切り替えて、許可ステートメントを確認します。結果: テーブルの作成と権限を個別に提供できるため、実行漏れを減らすことができます。スキーマが存在する場合、付与ターゲットは同じ修飾テーブル名に従います。
3. `ORM` に切り替え、ターゲット フレームワーク (Prisma、TypeORM、SQLAlchemy、GORM、JPA) を選択して、対応するモデル コードを生成します。結果: モデル コードをビジネス プロジェクトに直接貼り付けることができるため、手動による翻訳が削減されます。
4. `View/Routine` に切り替えて、構成されたビュー DDL またはストアド プロシージャ、関数、トリガー スケルトンを確認します。結果: テーブルを超えて関連するオブジェクト ステートメントを一度に取得できます。
5. 必要に応じて、`Copy DDL`、`Copy DCL`、`Copy ORM`、または `Copy View/Routine` をクリックします。結果: SQL がクリップボードにコピーされ、レビュー ドキュメントまたは実行システムに直接貼り付けることができます。
6. さらに編集スペースが必要な場合は、出力パネルの上部にある折りたたみボタンをクリックして、右側の領域を非表示にします。結果: フィールド構成テーブルの表示領域が増え、大規模なテーブルを編集できるようになります。
7. 上部のバーで「`Share`」をクリックします。結果: システムはアクセス可能な読み取り専用リンクを生成し、デフォルトの有効期間で自動的にコピーします。共有コンテンツは、現在の `Schema Name` とテーブル構造を保持します。
8. 受信者がリンクを開いた後に編集を続ける必要がある場合は、ページ プロンプトで `Save as copy and edit` をクリックします。結果: システムはホームに戻り、元の共有ビューを変更せずに編集可能なコピーをロードします。
9. コラボレーション中は、`Docs`、`Language`、`Theme` などの上位エントリを使用します。結果: 共同作業者は、ガイダンスをすばやく確認し、ロケールに一致するドキュメントを開いて、読み取り設定を調整できます。

## いつ完了するか

- 必要な DDL、DCL、ORM、またはビュー/ルーチンが正しくコピーされ、送信されていること。
- 共有リンクはアクセス可能であることが確認されており、受信者は完全な読み取り専用コンテンツを表示できます。
- 現在のテーブルでスキーマが使用されている場合、コピーされた SQL と共有ページの両方に修飾されたテーブル名が表示されます。
- さらに編集が必要な場合は、編集可能なコピーに正常に変換されています。
- 出力パネルの折りたたみ/展開状態は、現在の作業習慣と一致します。

## よくある落とし穴

- 共有ページはデフォルトでは読み取り専用であり、オンライン エディタとして直接使用することはできません。
- スキーマが環境境界の一部である場合は、コピーする前に、DDL / DCL に予期される修飾テーブル名がすでに含まれていることを確認してください。
- DCL ではなく DDL のみをコピーすると、同期された権限の付与なしでテーブルが作成される可能性があります。
- 共有リンクの有効期限が切れます。重要なレビューウィンドウについては、リンクを再生成します。
- ORM モデル コードは現在のフィールド構造スナップショットから生成されます。フィールドの変更は再コピーする必要があり、ビジネス プロジェクトに自動的に同期されません。

## データベースのバージョンと対象オブジェクト

- Oracle のテーブル DDL は `PUBLIC SYNONYM` を自動生成しません。同義語が必要な場合は、必要な権限を持つ管理者が別途作成してください。公共同義語の名前にスキーマ修飾は付けませんが、参照先テーブルには付けられます。
- MySQL の TEXT、BLOB、JSON などの定数デフォルト値は `DEFAULT ('{}')` のような式で出力され、MySQL 8.0.13 以降が必要です。旧バージョンではこの種のデフォルト値を削除し、互換データベースでも実際のバージョンで対応を確認してください。
- MySQL 系の文字列はバックスラッシュによるエスケープが有効な設定に合わせて出力されます。`NO_BACKSLASH_ESCAPES` を有効にしたセッションでは、実行前に文字列の意味を確認してください。
