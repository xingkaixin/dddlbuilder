# テーブルとフィールドの設定

このページでは、テーブル設定エリアと「フィールド」の表にある各項目の入力方法と、フィールドの表のツールバーにある補助ツールについて説明します。

## 利用場面

新しいテーブルを作成するとき、または既存のテーブルでフィールドや制約を追加・変更するときに使います。

---

## 設定ガイド

### 1. テーブルレベルの基本メタデータ
上部のテーブル設定エリアで、次の項目を入力します。
- 「データベースの種類」：対象のデータベースを選びます（MySQL、PostgreSQL、Oracle など）。
- 「テーブル名」と「テーブルコメント」：例えば `order_item` と `注文明細表` です。
- 「スキーマ名」（任意、「プロパティ」内）：対象のデータベースがスキーマでオブジェクトを区別する場合に入力します。例えば `sales` と入力すると、テーブル名は `sales.order_item` と出力されます。スキーマをテーブル名に含めないでください。

### 2. フィールドと制約の入力
「フィールド」の表で、フィールドごとに次の項目を設定します。
- 「フィールド名」と「コメント」：フィールドの識別子と説明です。
- 「タイプ」：現在のデータベースがサポートする型を入力します（`BIGINT`、`VARCHAR(255)`、`DECIMAL(10,2)`、`JSON` など）。
- 「NULL 許容」：チェックを外すと `NOT NULL` が生成されます。
- 「デフォルトの種類」と「デフォルト値」：デフォルトの種類は「なし」「自動インクリメント」「定数」「SQL 式」「現在の時刻」「UUID」から選べます。具体的な値が必要な場合は「デフォルト値」に入力します。
- 「更新時」：「現在の時刻」を選ぶと `ON UPDATE CURRENT_TIMESTAMP` が生成されます。

### 3. 編集のヒント
- ツールバーの「行の追加」をクリックすると、表の末尾に空の行が追加されます。横のプラス・マイナスボタンで、1 回に追加する行数を変更します。行頭のハンドルをドラッグすると、フィールドの順序を変更できます。
- 表を横にスクロールする必要がある場合は、「固定」スイッチをオンにすると先頭の数列が表示されたままになります。プラス・マイナスボタンで固定する列数を変更します。
- 「テンプレートの適用」をクリックすると、保存済みのフィールドテンプレートを挿入できます。例えば `created_at`、`updated_at`、`created_by` の監査フィールド一式です。同じメニューで「現在の行をテンプレートとして保存...」を選ぶと、現在のフィールドをテンプレートとして保存できます。

### 4. 業務メタデータと補助ツール
- **論理列挙（Logical Enum）**：ステータスコードのように取り得る値が限られるフィールドでは、「タイプ」セルの「列挙値の編集」をクリックし、ダイアログで列挙値、中国語と英語のコメント、カラータグを入力します。列挙の情報はテーブルと一緒に保存されます。
- **容量の見積もり**：「データツール」メニューで「サイズの見積もり」をクリックし、想定行数を入力します。見積もり結果は生データ、インデックス、オーバーヘッドに分かれます。容量計画の参考値であり、実際の使用量の正確な値ではありません。
- **スキーマリント**：編集エリア下部の「スキーマリント」をクリックすると、命名規則に合わない名前、リスクのあるフィールドの型、主キーの欠落などの問題を確認できます。
- **Mock テストデータ**：「データツール」メニューで「モックデータ」をクリックすると、フィールドの型に応じたテストデータを生成します。INSERT SQL、CSV、JSON で出力できます。

---

## 確認と完了の目安

- [ ] 業務に必要なフィールドがすべて入力され、型と長さが正しい。
- [ ] 主キーと NOT NULL 制約が設定され、デフォルト値が必要なフィールドに「デフォルトの種類」が設定されている。
- [ ] 「DDL」タブの SQL が完全で、構文エラーや空のプレースホルダーがない。
- [ ] 「スキーマリント」に「エラー」レベルの問題がない。

## 注意事項とトラブルシューティング

::: warning フィールドの型と長さの変更
フィールドの型を変更したり、フィールドの長さを短くしたりすると、DDLBuilder は「データ型変更のリスク」または「フィールド長短縮のリスク」を表示し、変換の失敗、切り捨て、データ損失の可能性を説明します。内容を確認したうえで「それでも変更」をクリックするか、「キャンセル」をクリックして変更を取り消します。
:::

- **予約語**：フィールド名が対象データベースの予約語（`order`、`group` など）の場合、表に「フィールド名は予約されたキーワードです」と表示されます。DDL を生成するときは、そのデータベースのルールに従ってフィールド名を引用符で囲みます。
- **外部キーの前提条件**：外部キーを設定する場合や ER 図で線をつなぐ場合、参照先のフィールドは単一フィールドの主キーまたは一意インデックスの列である必要があります。両端のデータ型にも互換性が必要です。
