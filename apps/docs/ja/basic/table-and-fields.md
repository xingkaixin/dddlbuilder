# テーブルとフィールドの設定

このガイドでは、テーブルの基本メタデータ、フィールド（カラム）定義、データ型、制約条件、および高度な補助機能の設定手順を詳しく解説します。

## 概要

白紙の状態から新しい業務テーブルを作成する場合でも、既存のテーブル構造を拡張・修正する場合でも、対象データベース方言の構文とデータ型規則に準拠した DDL を迅速に作成できます。

---

## 設定手順とポイント

### 1. テーブルレベルの基本設定
上部のテーブル設定ヘッダーで基本識別情報を設定します。
- **データベースタイプ**: 対象の本番環境に合わせて方言（MySQL、PostgreSQL、Oracle、SQL Server など）を選択します。
- **テーブル名と表示名**: 物理テーブル名（例: `order_item`）および日本語の業務名称（例: `注文明細表`）を入力します。
- **Schema Name（任意）**: スキーマ分離を行う環境（例: `sales.order_item`）では、専用の `Schema Name` 欄に入力します。テーブル名欄に手動で `schema.table` と入力する必要はありません。

### 2. フィールドと制約の定義
「フィールド設定」テーブルでカラムの属性を設定します。
- **フィールド名と日本語名**: 物理カラム名と業務上の意味を入力します。
- **データ型**: 方言に対応したデータ型（`BIGINT`、`VARCHAR(255)`、`DECIMAL(10,2)`、`JSON` など）を選択します。
- **NULL 許容**: `NOT NULL` または `NULL` を明示的に指定します。
- **デフォルト型とデフォルト値**: 定数、空文字列、現在時刻（`CURRENT_TIMESTAMP`）、UUID、式などのデフォルト値を設定します。
- **更新ポリシー**: 日時カラムなどに対して、`ON UPDATE CURRENT_TIMESTAMP` などの自動更新動作を指定できます。

### 3. 効率的な編集機能
- **行の一括追加と並べ替え**: 「行を追加」ボタンから複数行を一度に追加できます。左側のドラッグハンドルでカラムの順序を直感的に並べ替えられます。
- **列の固定とコンパクト表示**: カラム数が多い場合は「列固定」で主要な識別列を固定できます。画面が狭い場合は「コンパクトレイアウト」に切り替えて情報密度を高められます。
- **フィールドテンプレートの再利用**: 「テンプレート適用」から一般的な共通カラム（`created_at`、`updated_at`、`created_by` など）を一括挿入したり、現在の設定をチーム用カスタムテンプレートとして保存できます。

### 4. 業務メタデータと高度な補助機能
- **論理列挙型（Logical Enum）**: ステータスコードなどのカラムでは、行内の列挙型エディターを展開して値・表示名・カラーバッジを設定できます。このメタデータは保存され、チーム間での認識統一に役立ちます。
- **ストレージ容量の見積もり**: 「容量見積もり」をクリックして想定行数を入力すると、1行のバイト数とインデックスのオーバーヘッドを合算した正確な物理ディスク使用量を推計できます。
- **Schema Lint（仕様チェック）**: チェックパネルを開くと、命名規則違反、危険なデータ型、主キー欠落などの潜在リスクを自動スキャンします。
- **Mock テストデータ生成**: 「Mock データ」ボタンからデータ型に応じた検証用データをワンクリックで生成し、SQL INSERT や JSON/CSV 形式でエクスポートできます。

## 完了のチェックリスト

- [ ] 業務上必要な主要フィールドが過不足なく定義され、型と長さが適切である。
- [ ] 主キーと NOT NULL 制約が正しく設定されている。
- [ ] 右側の DDL パネルに、構文エラーのない SQL がリアルタイム出力されている。
- [ ] Schema Lint パネルで高リスクなエラー警告が出ていない。

## 注意事項

::: warning フィールドの型変更時のリスク
既存の運用テーブルでカラムのデータ型を変更する際、データの切り捨てや精度低下のリスクがある場合は警告ダイアログが表示されます。内容を必ず確認してください。
:::

- **予約語の回避**: カラム名がデータベースの予約語（`order`、`status`、`group` など）と重複した場合、警告が表示され、DDL 生成時に適切なエスケープ引用符が付与されます。
- **外部キー設定の要件**: 外部キーの設定や ER 図での接続を行う際、参照先カラムは単一カラムの主キーまたは一意キーであり、かつデータ型の互換性が必要です。
