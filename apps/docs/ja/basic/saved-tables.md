# 保存されたテーブルとドラフトボックス

## これは誰に向けたものですか

複数のテーブルを長期間維持するユーザーの場合は、プランを繰り返し切り替え、プロジェクトごとにスキーマを整理します。

## これで解決すること

一時的なデザインと正式に保存されたバージョンを個別に管理し、フォルダーやゴミ箱による偶発的な操作のリスクを軽減し、複数のドラフトを介して異なるスキームを並行して検討できます。

## ステップ

1. [テーブル構成] 領域で [保存] をクリックし、名前を入力します。結果: 現在のテーブルが「保存されたテーブル」に追加され、繰り返しロードできるようになります。テーブルで `Schema Name` が使用されている場合、テーブル構成の残りの部分と一緒に保存されます。
2. `Saved Tables` をクリックしてサイドドロワーを開き、名前またはデータベースの種類で検索します。結果: ターゲットテーブルを素早く見つけることができます。
3. 保存されたテーブルを選択し、ワークスペースにロードします。結果: 現在の編集領域がそのテーブルに切り替わり、ロードされたステータスが表示されます。 `Schema Name`、テーブル名、フィールド、インデックスが一緒に復元されます。
4. 名前を変更するには、リストから `Rename` を実行します。結果: ネーミングがすっきりします。
5. クリーンアップするには、リストから `Delete` を実行します。結果: テーブルはすぐに消えるのではなく、ゴミ箱に移動します。誤って削除した場合は、ゴミ箱から `Restore` をクリックします。
6. 完全にクリーンアップするには、ゴミ箱に入り、`Empty Trash` を実行します。結果: ゴミ箱内のテーブルは完全に削除され、復元できなくなります。続行する前に確認してください。
7. `Create folder` を使用し、テーブル項目をドラッグし、フォルダーをドラッグして構造を整理します。結果: 同じビジネス ドメイン内のテーブルをグループ化でき、リストがより明確になります。
8. 一時的な作業に戻るには、左側のワークスペース サイドバーで `Draft box` またはドラフトに切り替えます。結果: 保存されたテーブルに影響を与えることなく、名前のないドラフトを続行できます。ドラフト `Schema Name` もワークスペースに保存されます。複数のドラフトを共存させることができ、サイドバーからすばやく切り替えることができます。
9. サインイン後、フォルダー構造、ゴミ箱の状態、および下書きが保存されたテーブルと段階的に同期されます。結果: 別のデバイスにサインインすると、保存されたテーブル、フォルダー グループ、ゴミ箱、および下書きが自動的に復元されます。
10. 同期ステータスを確認する必要がある場合は、ヘッダーのプロファイルをクリックし、`Settings` を開き、`Workspace Sync` タブに移動して、`Sync now` をクリックします。結果: システムはクラウドの変更をプルし、ローカルの保留中の変更をプッシュし、ローカルの同期状態をリフレッシュします。競合が発生した場合、設定には保留中の数と競合の詳細が表示されます。
11. 手動でバックアップまたは復元する必要がある場合は、「`Workspace Sync`」タブで `Upload to cloud` または `Download from cloud` を使用します。結果: ワークスペース全体 (保存されたテーブル、下書き、フォルダー、ゴミ箱) をこのデバイスからクラウドにアップロードするか、クラウドからダウンロードして現在のデバイスを上書きできます。どちらの操作でも、誤って上書きされないようにするために確認が必要です。
12. 初めてサインインするときに、ブラウザーに匿名のローカル データが存在する場合は、移行プロンプトが表示されます。結果: 移行の開始後、匿名ワークスペースから保存されたテーブル、ドラフト、フォルダーがアカウントにバインドされます。名前の競合がある場合、システムは既存のクラウド コンテンツを上書きせずにコピーを自動的に保存します。

## ローカルコピーとクラウド同期

同じブラウザーでアカウントのワークスペースを開いたことがあれば、再読み込み時はローカルコピーを先に復元します。認証確認とクラウド同期はバックグラウンドで進むため、クラウドの応答を待たずに作業を続けられます。

- ネットワークや認証 API が一時的に利用できなくても、ローカルの内容は閲覧・編集できます。セッションの有効期限が切れた場合は、元のアカウントで再度サインインするとクラウド同期を再開できます。別のアカウントへ切り替えても、元の内容は引き継がれません。
- クラウドの内容をまだ取得していない新しいデバイスでは、初回同期が未完了であることを表示します。クラウドのワークスペースが空という意味ではありません。サインインと接続を維持してください。先にローカルで内容を作成し、後で自動的にマージすることもできます。
- サインアウト時は現在のページの編集を一時停止し、クラウドの確認を待ちます。確認できない場合はサインアウトを中止し、ローカルデータを保持します。同期を復旧してから再試行してください。サインアウトに成功すると、そのアカウントのローカルコピーは削除されます。
- ローカルコピーを開けたことは、クラウド同期の完了を意味しません。同期が完了する前にブラウザーのデータを消去しないでください。

これらの動作には、ページを読み込めることとブラウザーのストレージが利用できることが必要です。オフラインでサイト全体を開き直したり再読み込みしたりすることは、現時点では保証されません。

## いつ完了するか

- 頻繁に使用するテーブルは名前を付けて保存され、リストから確実にロードできます。
- フォルダー階層はプロジェクトまたはビジネス ドメインごとに編成されます。
- ドラフト ボックスと保存されたテーブルを切り替えた後、ワークスペースの状態が期待どおりになります。
- テーブルがスキーマを使用している場合、`Schema Name` とテーブル名の組み合わせはリロード後も一貫したままになります。
- サインイン後、フォルダー、下書き、保存されたテーブルはデバイス間で一貫性を保ちます。設定の `Sync now` は同期状態を更新します。
- 削除されたテーブルはゴミ箱から見つけられ、必要に応じて復元できます。

## よくある落とし穴

- ロードされているが変更されていないテーブルの場合、保存ボタンが無効になる場合があります。これにより、無意味な上書きが防止されます。
- 古いデータがテーブル名自体の内部で `schema.table` を使用していた場合、システムはロード時にデータを `Schema Name` と裸のテーブル名に分割します。ロード後に一度スポットチェックを行ってください。
- 削除されたテーブルはデフォルトでは完全に削除されず、ゴミ箱に置かれます。ゴミ箱を空にするだけで、ゴミ箱は回復できなくなります。
- ドラフトを保存済みのテーブルと間違えた場合、更新後に名前付きレコードが見つからないように見える場合があります。主要なマイルストーンで手動で保存します。
- サインインしない場合、フォルダー、下書き、保存されたテーブルは現在のブラウザーのローカル ストレージにのみ保存されます。デバイスを切り替えたり、ブラウザのデータを消去したりすると、復元できなくなります。クロスデバイス アクセスが必要な場合は、最初にサインインします。
- マルチタブ モードでは、現在のタブに保存されていない変更があるときに新しいテーブルをロードすると、保存を求めるプロンプトが表示され、偶発的な損失を防ぎます。
- 手動 `Upload to cloud` および `Download from cloud` は、選択した方向でワークスペース全体を上書きするため、実行する前にどのバージョンがターゲットであるかを確認してください。
