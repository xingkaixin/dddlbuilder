# 已保存表与草稿箱

## 使用对象

适合需要长期维护多张表、反复切换方案、按项目整理表结构的使用者。

## 解决问题

你可以把“临时设计”和“正式保存版本”分开管理，通过文件夹和回收站降低误操作风险，并通过多草稿并行探索不同方案。

## 操作步骤

1. 在表配置区域点击保存按钮并输入名称。结果：当前表进入“已保存表”列表，后续可重复加载；若当前表设置了 `Schema Name`，保存时会一并保留。
2. 点击 `查看已保存表` 打开侧边抽屉，按名称或数据库类型搜索。结果：你可以快速定位目标表。
3. 选择某张已保存表加载到工作区。结果：当前编辑区切换为该表，并显示加载状态；该表的 `Schema Name`、表名、字段与索引会一起恢复。
4. 需要改名时，在列表执行 `重命名`。结果：命名更统一。
5. 需要清理时，在列表执行 `删除`。结果：表被移入回收站，不会立即消失；若误删，可进入回收站点击 `恢复`。
6. 需要彻底清理时，进入回收站执行 `批量清空`。结果：回收站中的表被永久删除，不可恢复，操作前请确认。
7. 通过 `新建文件夹`、拖拽表项、拖拽文件夹整理结构。结果：同一业务域的表可以分组管理，列表更清晰。
8. 需要回到临时工作时，切换到 `草稿箱` 或左侧工作区侧边栏中的某个草稿。结果：你可以继续未命名草稿，不影响已保存表；草稿中的 `Schema Name` 也会随工作区一起保留。多个草稿可同时存在，通过侧边栏快速切换。
9. 登录账号后，文件夹结构、回收站状态与草稿会跟随已保存表自动增量同步。结果：在另一台设备登录同一账号时，已保存的表及其文件夹分组、回收站与草稿会自动恢复。
10. 需要确认同步状态时，点击顶部头像打开 `设置`，进入 `工作区同步` 标签并点击 `立即同步`。结果：系统会拉取云端变更、推送本机待同步内容，并刷新本地同步状态；若出现冲突，设置页会显示待处理数量和冲突明细。
11. 需要手动备份或恢复时，在 `工作区同步` 标签使用 `同步到云端` 或 `从云端下载`。结果：你可以将当前设备的完整工作区（含已保存表、草稿、文件夹与回收站）上传到云端，或从云端下载覆盖当前设备；上传/下载操作需要确认，避免误覆盖。
12. 首次登录时若浏览器中存在本地匿名数据，系统会弹出迁移提示。结果：点击开始迁移后，匿名工作区中的已保存表、草稿与文件夹会绑定到当前账号；如遇同名冲突，系统会自动另存为副本，不会覆盖云端已有内容。

## 本地副本与云端同步

同一浏览器中已打开过账号工作区后，刷新会先读取本地副本，身份检查与云端同步在后台进行，无需等待云端内容返回才能继续工作。

- 网络或身份接口暂时不可用时，本地内容仍可读取和编辑。若会话已过期，请重新登录原账号以恢复云端同步；切换到其他账号不会把原账号的内容带过去。
- 新设备尚未拉取过云端内容时，会显示“尚未完成首次同步”，这不代表云端工作区为空。保持登录并联网，也可以先创建内容，随后自动合并。
- 退出登录前，当前页面会暂停编辑并等待云端确认。确认失败时会取消退出、保留本地数据；恢复同步后再重试。退出成功后会清理该账号的本地副本。
- “已打开本地副本”不等于“云端已同步”。同步完成前不要清空浏览器数据。

上述行为以网页能够加载、浏览器本地存储可用为前提。目前不保证断网时重新打开或刷新整个网站。

## 完成标志

- 常用表已命名保存，并可从列表稳定加载。
- 文件夹层级已按业务或项目划分完成。
- 草稿箱与已保存表切换后，当前工作区状态符合预期。
- 若表使用了 schema，重新加载后 `Schema Name` 与表名组合仍与保存前一致。
- 登录账号后，文件夹、草稿与已保存表在多设备间保持一致；设置页的“立即同步”能刷新同步状态。
- 删除的表可在回收站找到并按需恢复。

## 易错点

- 已加载但未修改的表，保存按钮可能不可用，这是为了避免无效覆盖。
- 历史数据若曾把表名保存成 `schema.table`，系统加载时会自动拆分为 `Schema Name` 与纯表名；加载后建议抽查一次。
- 删除表后默认进入回收站，并非永久删除；只有清空回收站后才不可恢复。
- 误把草稿当已保存表时，刷新后可能找不到命名记录，关键节点请手动保存。
- 未登录状态下，文件夹、草稿与已保存表仅保存在当前浏览器本地，换设备或清空浏览器数据后将无法恢复。如需跨设备使用，请先登录账号。
- 多标签页下加载新表时，若当前标签存在未保存变更，系统会提示保存，避免意外丢失。
- 手动“同步到云端”和“从云端下载”会覆盖对应方向的完整工作区，执行前先确认当前设备和云端哪一份是目标版本。
