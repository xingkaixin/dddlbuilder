# DDL 输出与分享

## 使用对象

适合已经完成表结构配置，准备对外评审、协作确认或交付 SQL 的使用者。

## 解决问题

你可以明确“复制什么”“分享后别人能做什么”，避免协作时发错内容或误以为分享页可直接编辑。

## 操作步骤

1. 在右侧输出区先看 `建表 DDL`。结果：你能确认 `CREATE TABLE` 是否符合预期结构；若已填写 `Schema Name`，这里会输出带 schema 的限定表名。
2. 切换到 `授权 DCL` 再检查授权语句。结果：你能把建表与授权分开交付，减少执行遗漏；若有 schema，授权对象也会沿用限定表名。
3. 切换到 `ORM` 选择目标框架（Prisma、TypeORM、SQLAlchemy、GORM、JPA），生成对应模型代码。结果：你可以直接把模型代码粘贴到业务项目中，减少手工翻译。
4. 切换到 `视图/Routine` 查看已配置的视图 DDL 或存储过程、函数、触发器骨架。结果：你能一次性获取表之外的关联对象语句。
5. 按需点击 `复制DDL`、`复制DCL`、`复制ORM` 或 `复制视图/Routine`。结果：语句进入剪贴板，可直接粘贴到评审文档或执行系统。
6. 需要更多编辑空间时，点击输出面板顶部的折叠按钮收起右侧区域。结果：字段配置表格获得更大可视区域，便于大表编辑。
7. 点击顶部 `分享链接`。结果：系统生成可访问的只读链接并自动复制，默认有有效期；分享内容会保留当前 `Schema Name` 与表结构配置。
8. 接收方打开链接后如需继续编辑，点击页面提示中的 `保存为副本并开始编辑`。结果：系统返回首页并加载可编辑副本，不会改动原分享视图。
9. 协作过程中可使用顶部 `帮助文档`、`语言`、`主题` 入口。结果：成员可快速查阅说明、按语言进入对应文档并调整阅读环境。

## 完成标志

- 需要交付的 DDL、DCL、ORM 或视图/Routine 已正确复制并发送。
- 分享链接已验证可打开，接收方能看到完整只读内容。
- 若当前表使用了 schema，复制结果与分享页中的表名都保持为限定名。
- 需要继续修改时，已成功转成可编辑副本。
- 输出面板折叠/展开状态符合当前工作习惯。

## 易错点

- 分享页默认是只读，不能直接作为在线编辑页使用。
- 若你依赖 schema 做环境区分，复制前要检查 DDL / DCL 是否已经按预期带上限定表名。
- 只复制 DDL 不复制 DCL，可能导致建完表但权限未同步下发。
- 分享链接过期后会失效，建议在关键评审窗口重新生成一次。
- ORM 模型代码是按当前字段结构生成的，字段变更后需要重新复制，不会自动同步到业务项目。

## 数据库版本与对象范围

- Oracle 建表 DDL 不再自动附带 `PUBLIC SYNONYM`。如果业务依赖同义词，请由有相应权限的管理员单独创建；公共同义词名称不带 schema，目标表可以带 schema。
- MySQL 的 TEXT、BLOB、JSON 等字段使用常量默认值时，输出采用表达式形式，如 `DEFAULT ('{}')`，要求 MySQL 8.0.13 或更新版本。旧版本请取消这类默认值；兼容数据库需按实际版本验证支持情况。
- MySQL 系字符串按启用反斜杠转义的模式输出。若目标会话启用了 `NO_BACKSLASH_ESCAPES`，执行前需核对字符串语义。
