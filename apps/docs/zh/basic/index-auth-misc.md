# 索引、授权与杂项

本指南介绍如何为数据表配置高性能索引策略、权限控制语句（DCL）、底层存储引擎参数及 Routine 代码骨架。

## 适用场景

在完成字段定义后，进一步完善查询性能调优、权限发放以及底层物理存储选项，使表结构达到生产级上线标准。

---

## 核心配置指引

### 1. 索引配置（Index & Key）
进入“索引配置”标签页，为表构建查询加速与唯一性约束结构：
- **添加主键**：选择主键列并指定策略（通常一张表只能有一个主键）。
- **添加唯一索引（Unique Index）**：为业务唯一约束（如手机号、邮箱、租户编码）建立唯一索引。
- **添加普通索引（Index）**：从字段建议列表中选择单列或多列组装**联合索引**。
- **自定义索引名**：支持直接编辑或双击自定义索引名称；未命名时系统将按方言惯例（如 `idx_table_columns`）自动生成规范命名。

### 2. AI 索引优化顾问
如果不确定高频查询该如何建立联合索引：
1. 点击**AI 索引顾问**按钮。
2. 粘贴业务中的典型查询 SQL 或慢查询语句片段。
3. AI 结合当前表字段、已有索引与查询执行特征，自动给出**缺失索引推荐**、**冗余索引识别**、**列顺序优化**及**查询改写建议**。
4. 对认可的建议点击**添加索引**，即可一键加入索引配置并同步更新 DDL。

### 3. 授权配置（DCL 权限下发）
进入“授权配置”标签页，统一管理数据访问控制：
- 录入被授权的**用户或角色名称**（如 `app_user`、`readonly_role`）。
- 系统会在右侧“授权 DCL”面板自动生成对应的标准 `GRANT SELECT, INSERT, UPDATE, DELETE ON table TO user;` 语句。
- 当配置了 `Schema Name` 时，授权语句会自动匹配带命名空间的限定表名。

### 4. 杂项设置（存储参数与方言选项）
进入“杂项设置”标签页，开启开关后可按数据库方言配置底层存储参数：
- **引擎与编码**：MySQL / MariaDB 的 `ENGINE`（如 InnoDB）、`CHARACTER SET`（如 `utf8mb4`）及 `COLLATE`。
- **物理存储参数**：表空间（`TABLESPACE`）、PostgreSQL 的 `fillfactor`、Oracle 的 `PCTFREE`、`INITRANS` 等专属参数。
- **Routine 代码骨架**：按需选择存储过程（Procedure）、函数（Function）或触发器（Trigger）模板，右侧将生成规范的骨架代码，便于直接在数据库中填充业务逻辑。

## 校验与完成标志

- [ ] 核心查询与过滤字段已配置合理的索引，高基数唯一列已建立唯一约束。
- [ ] 索引命名规范无冲突，无字段为空的冗余索引。
- [ ] 授权对象已完整罗列，右侧 DCL 语句清晰无误。
- [ ] 开启杂项设置后，表级存储参数已正确写入 DDL 尾部。

## 常见注意事项

::: tip 杂项设置未生效排查
如果在杂项设置中调整了参数但右侧 DDL 没有变化，请确认是否已打开该面板顶部的**启用开关**。
:::

- **主键唯一性**：关系型数据库通常只允许一个主键。若已有主键，请勿重复添加。
- **授权对象为空**：当未录入授权用户时，右侧 DCL 显示为空是正常表现，建表 DDL 不受影响。
