# 索引、授权与杂项

## 使用对象

适合已经完成字段录入，准备补齐查询性能、访问权限和表级参数的使用者。

## 解决问题

你可以把“能建表”推进到“更接近可落地”，让索引、权限和表级参数与真实查询场景保持一致。

## 操作步骤

1. 打开“索引配置”，输入字段名并从建议中选择。结果：你可以快速组装索引字段组合。
2. 根据目标选择 `添加索引`、`添加唯一索引` 或 `添加主键`。结果：对应索引定义立即进入 DDL。
3. 如需调整索引名，直接编辑索引名称。结果：输出 SQL 使用你确认后的命名。
4. 如需从查询反推索引，点击 `AI 索引顾问`，粘贴典型查询 SQL 或慢查询片段。结果：系统会结合当前字段与已有索引给出缺失索引、冗余索引、字段顺序优化和查询改写建议。
5. 对可落地的索引建议点击 `添加索引`。结果：推荐字段组合进入索引配置，右侧 DDL 同步更新。
6. 打开“授权配置”，输入授权对象并添加。结果：右侧“授权 DCL”自动生成对应授权语句。
7. 打开“杂项设置”，先开启开关，再配置引擎、字符集、排序规则、表空间、fillfactor 或 Oracle 专属存储参数。结果：支持的数据库会把这些表级参数写入 DDL。
8. 如需 Routine 骨架，在杂项设置中选择存储过程、函数或触发器模板并调整参数。结果：右侧 Routine 输出区生成对应骨架代码。

## 完成标志

- 关键查询字段已配置索引，主键策略已明确。
- 若使用 AI 索引顾问，推荐索引已按查询场景复核后加入索引配置。
- 需要下发权限的对象已出现在授权列表中。
- 杂项设置开启后，右侧 DDL 能看到相应参数输出。

## 易错点

- 主键通常只允许一个，若已存在主键就不需要重复添加。
- AI 索引顾问需要表名、字段和典型查询 SQL；缺少任一项时，先补齐上下文再分析。
- 杂项设置未开启时，即使你选了参数也不会写入 DDL。
- 授权对象为空时，DCL 为空是正常状态，不是系统异常。
