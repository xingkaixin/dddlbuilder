# 导入与解析 SQL

本指南介绍如何将现有的 SQL 脚本、批量 DDL 或结构化数据文件（CSV、Excel、JSON Schema）逆向解析为可编辑的表结构模型。

## 适用场景

适用于存量系统重构、老项目数据库迁移、或从第三方接口定义、Excel 数据字典快速提取并生成标准表结构。

---

## 核心操作流程

### 1. 单表与多表 SQL 逆向导入
筑表师采用**「校验 → 预览 → 确认」**三步安全导入机制：
1. 点击顶部操作栏的**导入 SQL**按钮。
2. **选择源数据库方言**并粘贴待解析的 SQL 脚本（支持单条或多条 `CREATE TABLE`、`CREATE INDEX`、`ALTER TABLE`、`GRANT` 语句）。
3. 点击“下一步”进行语法解析与结构校验。
4. **在预览面板核验与微调**：
   - 检查解析出的字段、类型、主键、索引及授权对象。
   - 可在预览界面直接拖拽调整字段顺序或移除无关字段。
   - 若解析多张表，系统会检测潜在的重名冲突，并提供**覆盖、跳过、自动重命名**等合并策略。
5. 点击“确认导入”，结构将被原子写入当前工作区。若 SQL 包含命名空间（如 `CREATE TABLE sales.orders`），系统会自动将 `sales` 提取至 `Schema Name`，将 `orders` 填入 `表名`。

### 2. 结构化数据文件导入（CSV / Excel / JSON Schema）
1. 点击顶部操作栏的**导入数据**并选择文件类型：
   - **CSV 文件**：首行为表头字段名，系统根据前数行数据内容智能推断字段类型。
   - **Excel 表格（.xlsx / .xls）**：自动读取工作表首行作为字段名，推断常用数据类型。
   - **JSON Schema**：解析 `properties` 字段列表及其类型、格式与描述。
2. 上传文件后在预览界面核对字段与数据类型，按需手动纠正类型映射。
3. 确认导入后，字段结构自动填充至当前工作区。

---

## 支持语句与文件规范

| 格式 / 来源 | 支持语法与对象规范 | 解析行为说明 |
|---|---|---|
| **SQL 脚本** | `CREATE TABLE`、`CREATE INDEX`、`ALTER TABLE`、`GRANT` | 精准提取列约束、默认值、注释、联合索引及权限 |
| **CSV 文件** | UTF-8 编码，英文逗号分隔，首行为表头 | 基于内容特征推断 INT、DECIMAL、VARCHAR、DATETIME |
| **Excel 文件** | 支持 `.xlsx`、`.xls` 格式 | 提取首行作为字段名，根据单元格数据推断类型 |
| **JSON Schema** | 标准 Draft-07 / 2020-12 规范 | 提取 `properties`，将 `string/integer/boolean` 映射为对应字段 |

---

## 校验与完成标志

- [ ] 导入完成后，工作区完整呈现解析出的表名、字段列表、约束与索引。
- [ ] 若源 SQL 包含 schema，`Schema Name` 与 `表名` 已正确拆分回填。
- [ ] 右侧 DDL 与 DCL 输出面板能准确生成目标方言的标准 SQL。

## 常见注意事项与排错

::: tip 方言不匹配排查
若导入时提示语法错误，请优先检查导入弹窗中的**源数据库方言**是否与 SQL 实际语法一致（例如将 Oracle 语法放入 MySQL 解析器）。
:::

- **超长 SQL 脚本处理**：为保证浏览器解析性能，包含数十张表的大型 SQL 脚本建议按业务模块分批导入。
- **文件编码与加密**：上传 CSV 时请确保文件保存为 UTF-8 编码；Excel 文件请先解除密码保护后再上传。
- **JSON 深度嵌套**：复杂多层嵌套的 JSON Schema 建议先扁平化提取核心实体属性后再导入。
