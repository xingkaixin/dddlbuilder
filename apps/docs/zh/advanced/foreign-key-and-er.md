# SQL 转 ER 图：MySQL 外键与表关系建模

打开[筑表师](https://ddl.xingkaixin.me/)开始关系建模。已有建表语句时，先按[导入与解析 SQL](/zh/advanced/import-and-parse)载入表结构；建模完成后，可继续[生成 ORM 模型](/zh/advanced/orm-generation)。

本指南介绍如何用筑表师的外键配置面板和 ER 关系图建立表关系，并设置外键约束。

## 示例：用户与订单的多对一关系

本例使用 **MySQL 物理外键**。一个用户可以有多笔订单，每笔订单必须引用一个用户；两侧关联字段均为有符号 `INT`。

### 准备两张表

复制以下 SQL，在[筑表师](https://ddl.xingkaixin.me/)中选择 MySQL，通过 **导入结构** 导入，并确认两张表均已保存到工作区。详细步骤见[导入与解析 SQL](/zh/advanced/import-and-parse)。

```sql
CREATE TABLE users (
  id INT NOT NULL,
  name VARCHAR(100) NOT NULL,
  PRIMARY KEY (id ASC)
);

CREATE TABLE orders (
  id INT NOT NULL,
  user_id INT NOT NULL,
  PRIMARY KEY (id ASC)
);
```

### 创建关系并检查 ER 图

1. 在表配置区域点击 **更多**，打开 **ER 关系图**，从 `orders.user_id` 拖向 `users.id`。
2. 选择 **物理外键**、**多对一**、**必须关联**，删除规则设为 `RESTRICT`，更新规则设为 `CASCADE`。
3. 将 **外键名称** 设为 `fk_orders_user`，不勾选 **为外键字段创建索引**。点击 **创建关系**，保存 `orders`。

关系方向如下，箭头从外键字段指向被引用的主键：

```text
orders.user_id (N) ───→ users.id (1)
```

ER 图应显示物理外键的实线。`users.id` 是主键，`orders.user_id` 为 `NOT NULL`，但不设置唯一约束，因此多个订单可以引用同一个用户。

### 核对生成的 SQL

选择 `orders` 后，建表 DDL 应包含以下内容（排版可能随格式设置变化）：

```sql
CREATE TABLE orders (
  id INT NOT NULL,
  user_id INT NOT NULL,
  PRIMARY KEY (id ASC)
);

ALTER TABLE orders ADD CONSTRAINT fk_orders_user FOREIGN KEY (user_id) REFERENCES users (id) ON DELETE RESTRICT ON UPDATE CASCADE;
```

实际执行时先创建 `users`，再执行 `orders` 的建表和外键语句。`RESTRICT` 阻止删除仍被订单引用的用户；`CASCADE` 在用户主键更新时同步修改订单的引用值。MySQL 表需使用支持外键的存储引擎，例如 InnoDB。

如果只需要记录业务关联，选择逻辑关系即可，但不会生成上述 `ALTER TABLE` 外键语句。接下来可以[生成 ORM 模型](/zh/advanced/orm-generation)，检查表结构如何映射为代码。

## 逻辑关系（不创建物理外键）

没有物理外键的系统也可以记录表间业务关联。源表和目标表必须先保存到工作区。

1. 在 ER 图中从源字段连接点拖向目标字段连接点。
2. 在向导中选择 **逻辑关系**，确认字段、基数、可选性，并填写业务说明。
3. 点击 **创建关系**。目标字段无需具备主键或唯一索引。

逻辑关系以虚线展示，标签显示基数与可选性，悬停可查看业务说明；外键配置列表也会标明“逻辑关系”。可以从图中或列表中删除关系，也可以在列表中修改关系名称。

逻辑关系仅记录设计意图，不创建物理外键、唯一索引或普通索引，也不修改字段可空性。DDL、ORM 和 ALTER/回滚输出均不包含该关系。关系随表保存、版本历史、分享及工作区同步保留。以下物理外键的目标唯一性和级联规则限制不适用于逻辑关系。

## 适用场景

适用于在多张业务表（如用户表与订单表、部门表与员工表）之间建立引用关系，设置级联更新和删除规则，并在 ER 关系图中查看工作区内所有表的关系。

## 操作流程

### 1. 在 ER 关系图中创建关系（推荐）
1. 确保源表与目标表均已保存至当前工作区。
2. 在表配置区域点击 **更多**，选择 **ER 关系图**。
3. 将源表字段左侧的连接点拖到目标表字段右侧的连接点。
4. 在 **创建表关系** 对话框中设置：
   - 核对对话框带入的源字段与目标字段。目标字段只能是单字段主键或唯一键。
   - **关系基数** 选择 **多对一** 或 **一对一**。选择一对一时，对话框会为源字段添加唯一索引。
   - **是否必须关联** 选择 **必须关联**（源字段设为 `NOT NULL`）或 **允许为空**（源字段设为 `NULL`）。
   - 设置 **删除引用记录时** 与 **更新引用键时** 的规则（`NO ACTION`、`CASCADE`、`SET NULL` 等），并决定是否勾选 **为外键字段创建索引**。
5. 点击 **创建关系**。外键约束、字段可空性与索引一起写入源表，ER 关系图显示新的关系线。

### 2. 通过外键配置面板手动创建
1. 切换至“外键配置”标签页。
2. 点击 **添加外键**。
3. 填写 **约束名称** 和 **目标表名**，选择 **本表字段**，再输入 **目标表字段**（回车添加）。
4. 按需设置 **删除时** 与 **更新时** 的规则。
5. 点击 **确认添加**。生成结果中的 DDL 随即加入 `CONSTRAINT ... FOREIGN KEY ... REFERENCES ...` 语句。

### 3. 浏览和整理 ER 关系图
- 拖动表节点调整位置，或点击工具栏的 **自动布局**。
- 用鼠标滚轮缩放画布，拖动画布浏览全图。
- 物理外键关系线的标签显示删除和更新规则，悬停可查看外键名称。点击标签旁的删除按钮会删除对应的外键约束。

## 校验与完成标志

- [ ] 外键配置列表和 ER 关系图都显示了新建的关系。
- [ ] 生成结果中的 DDL 包含外键约束语句。
- [ ] 一对一关系的源字段有唯一索引；常用于关联查询的外键字段有普通索引。

## 常见注意事项

::: warning 外键类型兼容性与引用要求
目标字段必须是单列主键或唯一索引列。源字段与目标字段的数据类型、有无符号（UNSIGNED）必须一致，否则在数据库执行时会报错。
:::

- 删除规则选择 `SET NULL` 时，源字段必须允许为空（`NULL`），不能设为 `NOT NULL`。
- ER 关系图按 Schema 名和表名查找被引用表。工作区中有多张同名表时，不显示这条关系线。
