# Mock 数据与逻辑枚举

本指南介绍如何使用筑表师生成高质量的 **Mock 测试数据**，以及如何在字段中配置直观的**逻辑枚举（Logical Enum）**元数据。

## 适用场景

适用于开发与联调阶段快速填充测试数据、验证 SQL 查询行为，以及为包含状态码、类型字典的字段建立标准业务取值规范与可视化标识。

---

## 核心操作指引

### 1. Mock 测试数据生成与导出
1. 确保表结构已完成字段与数据类型配置。
2. 在工具栏中点击 **Mock 数据** 按钮打开生成面板。
3. **设置生成参数**：
   - 指定生成数据行数（1–100 行）。
   - 预览生成结果，系统会根据字段类型（整数、浮点数、UUID、日期、邮箱、布尔等）自动填充格式合规的随机测试样本。
4. **导出数据**：
   - 选择导出格式：**SQL INSERT 语句**、**CSV 文件** 或 **JSON 数组**。
   - 点击导出或复制，直接导入本地测试数据库或 Postman 中进行接口调试。

### 2. 字段逻辑枚举（Logical Enum）配置
对于状态码、审核状态、用户类型等离散值字段：
1. 在“字段配置”表格中找到目标字段，点击展开行内的**枚举编辑器**。
2. 点击“添加枚举项”，录入**枚举值**（如 `10`、`PAID`）与对应的**显示名称**（如 `已支付`）。
3. **分配颜色标识**：为各枚举项选择专属颜色徽章（如绿色代表成功、红色代表拒绝、黄色代表待处理），在界面上实现业务状态一目了然。
4. **拖拽调整顺序**：通过左侧手柄自由拖拽枚举项调整业务显示优先级。
5. 枚举元数据会随草稿与已保存表自动持久化，便于团队协作时对齐字典定义。

---

## 校验与完成标志

- [ ] Mock 测试数据格式合规，能顺利执行导入并用于业务接口测试。
- [ ] 逻辑枚举已完整覆盖所有业务分支状态，颜色标识清晰直观。
- [ ] 重新加载已保存表后，枚举配置完好无损。

## 常见注意事项

::: tip 生产敏感数据安全
Mock 数据引擎生成的是合成随机样本，不包含任何真实业务隐私。请勿在测试环境直接使用未脱敏的真实用户数据。
:::

- **外键与唯一性依赖**：Mock 数据按单表字段类型独立生成，不会自动校验跨表外键级联关系，插入测试库前请注意依赖顺序。
- **方言原生枚举与逻辑枚举**：逻辑枚举作为元数据保存在筑表师中用于前端展示与文档化说明；若需数据库底层物理 `ENUM` 类型，请直接在字段类型中选择目标方言的 `ENUM`。
