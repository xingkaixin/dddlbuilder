# 评审与解释 SQL

## 使用对象

适合已经生成 SQL，准备做质量评估、风险排查和团队沟通说明的使用者。

## 解决问题

你可以先用“评审”发现结构风险，再用“解释选中”快速说明关键语句含义，减少评审沟通成本。

## 前置条件

- 当前右侧已有有效 DDL 输出。
- 你希望对现有语句做质量评审或片段解释。

## 操作步骤

1. 在“建表 DDL”区域点击“大师评审”。结果：系统开始分析当前 DDL 并生成评分与建议。
2. 查看评审结果中的问题描述与建议项。结果：你能快速识别高风险点和可改进项。
3. 对可执行建议点击“应用”。结果：建议会写回字段或索引配置，进入可继续复核状态。
4. 点击评审区的历史入口图标。结果：你可以查看同表历史评审记录并回看建议。
5. 在 SQL 代码区选中一个语句片段。结果：出现“解释选中”入口。
6. 点击“解释选中”查看 AI 说明。结果：你可以快速理解该片段意图并用于评审沟通。
7. 需要为表或字段补充注释时，可请求 AI 生成中文业务注释。结果：AI 自动为表与字段生成中文注释并回填到对应位置。

## 完成标志

- 当前 DDL 已完成至少一轮评审并有可读结论。
- 关键建议已按需应用或明确标记为不采纳。
- 团队成员可通过解释内容理解重点 SQL 片段。

## 易错点与失败处理

- 无有效 DDL 时无法评审：先补齐表结构并生成 DDL。
- 建议可应用不代表必须应用：涉及业务规则的项必须人工确认。
- 解释选中无响应：先确认你选中的确实是 SQL 文本片段。
- 评审历史为空：通常是当前表还没有成功完成过评审。
