# 视图与 Routine 配置

本指南介绍如何使用筑表师配置**视图（CREATE VIEW）**以及生成**存储过程（Procedure）**、**函数（Function）**、**触发器（Trigger）**的标准代码骨架。

## 适用场景

适用于除了基础物理表外，还需要统一管理数据库视图抽象层或初始化服务端存储过程与触发器逻辑的复杂工程场景。

---

## 核心操作流程

### 1. 视图（View）定义与 DDL 生成
1. 在配置区域找到**视图定义**面板。
2. 填写**视图名称**（如 `v_user_order_summary`）与标准的 **SELECT 查询语句**。
3. 若需指定对外列别名，在 SELECT 语句中使用 `AS` 显式声明。
4. 切换至右侧输出面板的**视图/Routine**标签页，系统将自动生成符合当前数据库语法的 `CREATE VIEW ... AS SELECT ...` 语句。
5. 点击**复制视图DDL**即可直接使用。

### 2. Routine（存储过程/函数/触发器）模板骨架生成
1. 在“杂项设置”或配置面板中找到 **Routine 模板**选择器。
2. 选择所需生成的对象类型：
   - **存储过程（Stored Procedure）**：生成包含输入输出参数（`IN` / `OUT`）与事务块的骨架代码。
   - **自定义函数（Function）**：生成带有返回值类型声明与计算主体的函数骨架。
   - **触发器（Trigger）**：配置触发时机（`BEFORE` / `AFTER`）与事件（`INSERT` / `UPDATE` / `DELETE`），生成规范的触发器头部与执行块。
3. 切换至右侧输出区的 **Routine** 视图，点击**复制Routine**获取代码骨架，并在数据库客户端中继续编写核心业务逻辑。

---

## 校验与完成标志

- [ ] 视图 DDL 语法与目标数据库方言标准完全吻合。
- [ ] 视图 SELECT 语句中引用的实体表与字段名准确无误。
- [ ] Routine 骨架代码已复制并在数据库中通过基础编译。

## 常见注意事项

::: tip 视图与 Routine 的业务逻辑填充
Routine 模板输出的是结构化语法骨架与边界封装，具体的内部计算与事务分支需由开发人员结合业务实际填充。
:::

- **视图依赖校验**：若视图查询中引用了尚未创建的表或字段，在数据库执行时会报错，请确保依赖的物理表优先创建。
- **方言差异**：存储过程与触发器在 Oracle（PL/SQL）、PostgreSQL（PL/pgSQL）与 SQL Server（T-SQL）间语法差异较大，切换数据库后需重新核对语法。
