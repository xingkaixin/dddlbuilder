# 视图与 Routine 配置

本页介绍如何在筑表师中定义视图（`CREATE VIEW`），以及如何生成存储过程、函数和触发器的代码模板。

## 适用场景

除了普通表，还需要管理视图，或者需要存储过程、函数、触发器的起始代码时使用。

---

## 核心操作流程

### 1. 视图定义与 DDL 生成
1. 在表配置区点击**表属性**，把**对象类型**改为**视图**。
2. 填写**视图名**（如 `v_user_order_summary`）。
3. 在**视图 SQL** 标签页的**查询 SQL** 中填写 SELECT 语句。需要指定对外列名时，在 SELECT 中用 `AS` 声明别名。
4. **CREATE OR REPLACE** 默认勾选，生成 `CREATE OR REPLACE VIEW`（SQL Server 下为 `CREATE OR ALTER VIEW`）。取消勾选则生成 `CREATE VIEW`。SQLite / D1 下始终生成 `CREATE VIEW`。
5. 生成结果的**建表 DDL** 标签页会生成 `CREATE VIEW ... AS SELECT ...` 语句，点击**复制DDL**即可复制。

### 2. Routine（存储过程、函数、触发器）模板
1. 在生成结果中点击**程序单元**标签页。SQLite / D1 下没有这个标签页。
2. 在**模板**中选择要生成的对象：
   - **自动更新时间戳触发器**：更新记录时，把指定的更新时间字段设为当前时间。
   - **审计日志触发器**：数据变更后，向审计表写入一条记录。
   - **存储过程**：填写参数（如 `IN p_user_id INT`）和逻辑体。
   - **函数**：填写参数、返回类型和逻辑体。
   - **自定义触发器**：填写触发表和逻辑体，生成 `BEFORE INSERT` 触发器（SQL Server 下为 `AFTER INSERT`）。
3. 点击**复制程序**复制代码，再在数据库客户端中补全业务逻辑。

---

## 校验与完成标志

- [ ] 视图 DDL 符合目标数据库的语法。
- [ ] 视图查询中引用的表名和字段名正确。
- [ ] 程序单元代码已在数据库中通过编译。

## 常见注意事项

::: tip 补全业务逻辑
程序单元模板只生成语句结构。存储过程、函数和自定义触发器的逻辑体需要你按业务编写。
:::

- 视图查询引用的表或字段不存在时，执行视图 DDL 会报错。先创建视图依赖的表。
- 存储过程和触发器的语法在 Oracle（PL/SQL）、PostgreSQL（PL/pgSQL）和 SQL Server（T-SQL）之间差异较大。模板按当前数据库类型生成，但你填写的逻辑体不会转换，切换数据库类型后要重新核对。
