# Documentation Agent Guide

This repository uses Astro for the documentation site. The site has no docs framework on top: layout, sidebar, outline and search live in `src/`.


## Structure

- Locale routes use fixed URLs under the `/docs` base:
  - Chinese: `/docs/zh/`
  - English: `/docs/en/`
  - Japanese: `/docs/ja/`
- Locale sources live under `zh/`, `en/`, and `ja/` in this app.
- Main sections (sidebar) are:
  - 基础指南 (basic)
  - 高级技巧 (advanced)
  - FAQ (faq)
  - 更新说明 (changelog)
- The sidebar and interface copy are defined in `src/lib/site.ts`.
- Any new or renamed page must be wired in `src/lib/site.ts`, and locale routes must stay consistent.
- Heading ids and URLs are public: `src/lib/slugify.ts` must keep producing the same ids, and `astro build` fails on a dead internal link or anchor.
- Markdown stays plain: `::: info|tip|warning Title` containers and `{#custom-id}` headings are the only extensions.


## Source of truth

- **Changelog page**: The Chinese version (`zh/changelog/changelog.md`) is the source of truth. The English and Japanese changelogs should be translated from the Chinese version. The root `CHANGELOG.md` mirrors the English entries.
- **All other pages**: The Chinese version (`zh/`) is the source of truth. English and Japanese translations should be based on the Chinese docs.
- Translated pages must keep the same routes and section structure as the Chinese source.

Only the Chinese documentation and the Chinese changelog are manually reviewed. Other translations may be auto-generated by AI agents.


## 写作规范

读者时间有限，要能读完就照着做。

- 先说明问题来源或功能用途，再给结论。写“本次修复了导入预览中排序按钮方向错误的问题”，不写“本次进行了若干优化”。
- 步骤写清条件、路径和顺序，一步一行。不写“更新代码然后重新部署即可”。
- 写明适用对象和前置条件，例如“需要登录”“仅 MySQL、MariaDB、TiDB 支持”。
- 区分已确认的行为和推测。没有核对过代码的行为不写成确定陈述。
- 不用模糊表达：“优化了一些细节”“做了一些改进”要改成具体改了什么。
- 不写空洞开场，直接进入主题。
- 术语统一：产品名、数据库名、功能名按界面和官方写法，全文一致；macOS 写作 macOS，域名小写。
- 截图和图表必须配说明，写清它展示什么。没有说明的图删掉。
- 段落短，说明类内容一条一行，不和叙事混写。
- Changelog 条目沿用现有格式和分类（新增、优化、修复），只写用户能感知的变更。

发布前检查：术语是否统一、前置条件是否遗漏、步骤能否复现、是否还有模糊词、图表是否有说明。
