## 共用约束

- 保留匿名用户现有本地功能。云端创建、更新和留言使用现有账号登录。
- 保留现有短期单表分享；项目文档与变更提案是独立记录，不改变原链接语义。
- 界面沿用已有按钮、表格、表单、主题与三语翻译。输入与主要操作放在同一组；阅读内容与编辑操作分开；窄屏按阅读顺序折行。
- 网络输入用共享 Schema 校验，表结构兼容交给 workspace-core 解码器；不可把无效响应当作空结果。
- 列表只返回摘要，内容按 ID 读取。所有写入检查归属，读取检查可见性。错误返回明确的登录、无权限/不存在、输入或并发冲突结果。
- 云端写入完成后才显示成功。不把发布内容自动写回工作区。
- 不新增后台同步、实时多人编辑、自动执行 SQL 或任意代码表达式。

## 1. 项目数据库文档设计

### 交互

在数据库工具中提供项目文档管理。作者从当前选中的多表字典创建文档，输入标题，选择“仅自己”或“持链接可读”。创建后得到固定地址。读取者打开独立阅读页面，查看标题、版本、更新时间、表目录、搜索和表间导航。阅读页不要求加载编辑工作区。

已有文档可重新发布选中的最新结构，ID 和 URL 不变，版本递增。切回“仅自己”即撤销外部访问。删除文档需明确确认。作者可重新读取已发布内容；草稿改动不自动影响读者。

### 数据与权限

新增 D1 文档记录：随机 ID、owner、title、visibility、revision、content、createdAt、updatedAt。内容包含选中的表和被引用字段标准的业务定义快照。标准快照只用于展示，不修改读者的本地标准库。

创建默认私有；持链接可读是用户显式选项。读取私有或不存在的非本人文档统一返回 404。所有者信息不暴露邮箱。响应 no-store，避免撤销后浏览器重新请求仍取旧缓存。已被下载的副本不提供远程撤回。

更新携带当前 revision，用单条条件 UPDATE 防止两个设备覆盖；冲突提示重新读取。记录上限、请求体大小、表数量和字段数均在服务端检查。沿用现有 USER_DB，不增加 KV 或 R2 绑定。

### 验收

创建、刷新页面、其他设备读取仍存在；匿名读者能读取持链接可读文档；私有/撤销后拒绝非作者；二次发布保持 URL 并增加版本；并发旧版本不能覆盖；输入 HTML 仅显示文本；跨浏览器字段标准仍可读。

## 2. 结构快照接入与刷新设计

### 交互

提供可下载的结构快照文件，以 JSON 封装方言和多表定义，并以版本号标识格式。支持从已保存表导出和从文件读取；读取后展示表列表及数量，让用户明确选择。

刷新采用“现有结构 + 新结构 → 预览 → 导出/应用”的流程。匹配键是方言、Schema、表名；同名字段保留原字段身份、业务说明、逻辑枚举和标准引用，数据库结构属性来自新快照。保留有效的逻辑关系；失去目标的关联提示处理。删除、新增与改名分开显示，不猜测名称变化。

实际数据库提取先给出本地 MySQL/PostgreSQL 的结构导出命令与格式说明。数据库凭据留在用户本地。普通 SQL 导入继续保留；新增快照用于保存完整模型元数据和后续刷新，不宣称任意 SQL dump 均可解析。

### 数据与失败语义

快照包含 format、version、tables 和 standards 标准业务摘要数组。文件在浏览器校验后才产生候选内容。空文件、超限、未知版本、重复表和会丢失属性的错误结构报错；刷新另行拒绝混合方言，首版支持 MySQL/PostgreSQL。刷新不自动覆盖用户当前编辑；应用需使用现有原子工作区入口，并清楚列明写入范围。若无法安全复用该入口，则通过明确的刷新结果文件完成交付，不提供伪应用按钮。

### 验收

导出/导入保持关系、标准与字段身份；刷新后结构来自新源、业务元数据来自旧源；不匹配项明确显示；坏文件不清空工作区；后续再次刷新不重复新增表。

## 3. 变更提案设计

### 交互

从两份 SQL 的比较结果创建提案，填写需求标题与修改原因。创建时固定基线、目标、显式字段改名映射。提案形成独立地址，读者看到结构差异、迁移限制和脚本。

登录的读者在公开提案下填写对象位置和评论；作者可以标记已处理/重新打开。评论固定绑定该提案的结构快照。首版提案结构不可变；需要调整时创建后续提案，避免在原评论下面替换目标版本。

作者可以关闭外部访问。未登录读者可查阅公开提案，留言需要登录；界面给出明确入口。首版没有审批通过状态，不将“评论已处理”宣称为数据库发布许可。

### 数据

提案记录包含 owner、title、reason、visibility、固定的 before/after/renames、时间。评论包含 proposalId、authorId、作者显示名称、target、body、resolved、createdAt。评论排序稳定，数量有上限，作者处理操作检查提案所有权。删除提案级联删除评论。

### 验收

非作者不能替换快照或处理评论；私有提案无法被其他人读取/留言；无效对象位置不导致执行；包含脚本内容的留言按文本渲染；评论保存后重载仍存在；固定版本报告与生成器一致。

## 4. 测试数据场景设计

### 规则

场景以表身份和字段名称关联，可配置：空值比例；枚举值权重；整数/小数范围；日期范围；基于另一个日期字段增加固定时间偏移。所有选项声明式，不支持 JavaScript、SQL 或其他用户代码。

默认规则保持原生成语义。受规则影响的字段必须通过类型和约束检查。物理外键字段由关联生成器决定；不能用自定义规则覆盖后制造无效引用。主键/唯一键保持唯一性校验。日期引用先验证存在、类型和依赖，不接受循环。

同一结构、场景、行数、种子应生成相同结果。场景保存在当前浏览器并提供 JSON 导入导出；名称相同也不能静默覆盖其他配置。结构变更导致字段缺失时明确报错。

### 界面

在关联测试数据中选择表与字段，配置规则列表，设置名称并保存。加载场景后可检查规则再生成。任何配置修改立即清除旧结果。约束失败时不交付部分 SQL。输出保留现有 SQL/JSON 下载和前五行预览。

### 验收

权重分布、空值、范围、日期偏移可重复；唯一冲突和不兼容类型可解释；父子键仍一致；读取场景后等价复现；损坏场景不会替换有效配置。

## 5. MySQL → PostgreSQL 兼容性报告设计

首版输入严格 MySQL 结构快照，输出逐表/字段的分类和 Markdown 报告：有直接映射的结构、需要人工核查的结构、不在评估范围的结构。分类依据固定规则，不调用 AI。

检查至少包含整数范围与 unsigned、自增、字符类型、decimal 精度、日期与零日期、JSON、二进制、enum、默认表达式、ON UPDATE、索引与外键、引擎/字符集/排序规则、分区及存储对象。不能仅靠字符串替换输出“成功”。

报告展示原定义、候选目标类型、原因与下一步。即使所有字段有候选映射，也说明评估未检查业务查询、存量数据或运行时行为。首版不输出可直接执行的跨库迁移脚本；用户仍可在现有编辑器确认目标模型后生成 DDL。

验收：范围扩大导致的 unsigned 风险可见；表达式和 ON UPDATE 不被静默当作可兼容；未知类型有明确结果；报告保留全部表与分类统计；不修改输入状态。

## 模块归属

- shared-types：交付对象的网络 Schema、快照及声明式场景契约。

### 实施细化

- 文档和提案共用 `schema_publications`，以 kind 区分。同一作者、可见性、并发版本与删除策略由同一模块负责；提案内容不可变，评论仍为独立子表。
- 结构刷新通过结果文件与重新发布交付，不写入工作区。预览显示字段、索引、关系差异并可下载报告。本地数据库接入提供官方客户端命令与严格解析流程，不宣称任意 dump 自动转换成功。
- 公开内容只包含结构和所引用标准的摘要；私人工作区身份不进入链接或评论响应。
- 评论 `target` 是作者可读的位置说明，不执行、不解释为数据库对象权限。处理状态仅用于讨论。
- 造数概率规则不承诺小样本的精确比例；同一配置按种子可复现。场景仅恢复配置，用户须选择对应表。
- 成本：复用现有 USER_DB，不新增运行时绑定或外部服务。文档按打开读取、手动更新写入；评论按操作写入。每账号 100 份发布、每份 512 KiB，每提案 200 条评论。发布需要账号，离线快照、报告和场景无需账号。
- 不确定性：数据库真实导出语法及存量数据语义仍需用户核对；没有生产连接凭据，不声称完成生产数据库迁移测试。增长效果需要后续观察实际使用，不能从功能上线推导。

### 回归重点

- 使用真实 SQLite 和全量迁移验证发布归属、私有权限、条件更新及评论级联删除；Workerd E2E 验证 HTTP 协议、Cookie 会话、跨 Origin 拒绝和撤销。
