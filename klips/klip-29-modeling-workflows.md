# 查询设计、业务模块、SQLite/D1 与影响分析

日期：2026-09-18。用户授权在 main 完成可行性评估、详细设计、实现、分步提交、测试和 push；最终提交的 CI 全部通过后交付。不涉及 AI 或 SQL 执行服务。

## 1. 可行性与决策

| 功能 | 已有基础 | 主要风险与处理 | 结论 |
| --- | --- | --- | --- |
| 可视化查询 | 表快照、字段、物理外键和逻辑关系；MySQL/PostgreSQL 方言 | 多路径不能猜测；复合关系必须完整；聚合与分组必须一致；过滤值使用参数 | 通过：关系驱动的 SELECT 设计，显式选择连接，纯浏览器生成 |
| 多表模块 | 单表模板、工作区批量写入、关系与多方言 DDL | 名称冲突造成引用指向错误；多表部分保存；实例间字段身份重复 | 通过：三个内置模块，整组生成、全组冲突检查、一次批量保存，不覆盖旧表 |
| SQLite/D1 | 方言策略、共享 DatabaseType、ORM 输出及 D1 部署经验 | SQLite 约束不能用 ALTER ADD；INTEGER PRIMARY KEY 特殊语义；D1 无任意 schema；旧功能不能误输出 | 通过：增加 SQLite 建模、CREATE 与 Drizzle SQLite 输出；D1 使用同一方言和初始化 SQL；暂不支持 SQLite SQL 导入、自动 ALTER、DCL、routine |
| 影响分析 | 保存快照中的索引、外键、逻辑关系、分区和分片配置 | 未导入对象不可知；名称/Schema 歧义；文本匹配不能冒充视图解析 | 通过：精确报告已选模型的字段依赖和相关字段；首版不推测视图、应用代码或外部对象 |

现有生产部署为静态资产 + Worker/Hono + D1 + KV + workspace Durable Object。四项计算在浏览器和 ddl-core 执行。保存业务模块沿用已有 Y.Doc 批量写入；无需新绑定、队列、数据库服务、后台进程或用户数据库凭据。查询输入 SQL 仍走现有解析 API；查询条件仅用于本地生成参数。新增 SQLite 表通过现有 workspace 编解码和同步协议持久化。无新生产依赖。

实现依赖顺序：查询核心与 UI；模块核心与 UI；SQLite 方言及能力门禁、Drizzle 与初始化导出；影响分析；集成验收和文档。每块保留独立提交。上线依据功能验收，不把未经验证的增长预测当成通过理由。

## 2. 查询设计器

入口：数据库工具中的“查询设计”。来源复用已保存表、严格 SQL、结构快照。只接受单一 MySQL 或 PostgreSQL 的普通表集合。选择根表，逐次从已经加入查询的表选择一条关系连接新表；可以选 INNER/LEFT JOIN。物理/逻辑关系均可作为建议，复合字段成组生成 ON，多个关系逐条呈现。首版不提供自连接、循环连接、子查询、UNION、任意 SQL 表达式或 SQL 反向编辑。

用户选择输出字段及可选聚合（COUNT/SUM/AVG/MIN/MAX）和别名，添加 AND 过滤条件（等于、不等于、大小比较、LIKE、IS NULL、IS NOT NULL），选择分组字段、输出列排序和 LIMIT。提供 COUNT(*)。聚合查询的非聚合输出必须被分组；不存在的字段、断开的连接、重复别名、非法排序/限制阻止导出。SUM/AVG 限定数值字段；LIKE 限定文本字段。空值用专门运算符表达。

输出为格式化 SQL 与有序参数 JSON；MySQL 使用 ?，PostgreSQL 使用 $1…；所有值保留字符串，NULL 条件不占参数位置，不将过滤值拼进 SQL。标识符来自已验证模型并按方言引用。支持复制和下载。修改来源清空查询配置，修改配置立即重新计算，失败时移除旧 SQL，避免过期结果。

核心接口由 queryDesigner.ts 拥有：关系候选发现、查询输入类型、构建 SQL/参数。UI 拥有配置，派生所有候选与输出，不存一份重复的 SQL 状态。配置仅存本次弹窗，不同步、不执行、不上传。关闭或切换账号清除。

验收：两表复合连接、两条可选关系、LEFT JOIN、按客户 SUM 金额、多个参数与引号保真、NULL 过滤、分组错误、缺失字段、跨方言拒绝、输入变化后导出同步更新。

## 3. 多表业务模块

入口：数据库工具中的“业务模块”。内置 RBAC（用户、角色、权限、用户角色、角色权限）、预约（资源、时段、预约）、库存（商品、仓库、库存、库存流水）。模板包含字段说明、主键、必要唯一键和物理外键；说明其设计假设，不宣称覆盖完整业务。

选择 MySQL/PostgreSQL、模块、表名前缀与主键方案（整数自增或应用提供的字符串 ID）。前缀只允许明确的标识符字符，所有表名、索引和外键引用一起生成。字段身份、索引和关系身份为每次实例新建；字段业务名称不被前缀改变。模板不含任意代码，不接受外部模板执行。

先展示表清单、字段/关系和 SQL，可下载结构快照、建表 SQL，并保存整组到工作区。已有同名显示名或同方言/Schema/表名冲突时阻止整组保存，用户调整前缀；不跳过、不自动重命名单表、不覆盖。使用 workspace 权威的批量导入事务，成功后刷新保存表缓存，失败不报告成功。新表可继续在正常编辑器编辑并参与 ER 图、字典与查询。

模板定义放在 ddl-core，实例化返回 PersistedState[]。SQL 输出复用 buildDDL，先创建所有表和索引再追加外键，避免模板顺序导致引用未创建的表。首版不做社区模板市场，也不自动复制项目代码。

验收：三个模块各两种数据库、两种主键方案；跨表类型一致；复合唯一键；不同实例身份不复用；前缀正确传递；冲突时整组不写；保存后刷新仍存在且关系可解析。

## 4. SQLite / D1 与 Drizzle

主编辑器增加 SQLite / D1 数据库选项，持久化 dbType=sqlite；D1 是交付目标而非第二套方言。使用独立 SQLite 生成模块拥有完整 CREATE，主键、唯一约束和外键在 CREATE 内；普通/唯一索引单独 CREATE INDEX。支持 INTEGER、TEXT、REAL、BLOB、NUMERIC 存储类型，以及明确映射的常用逻辑类型。显式说明 SQLite 类型亲和性不保证长度、小数精度与 JSON 校验。

仅单列 INTEGER 主键允许自增；配置自增但缺失主键、复合主键自增等情况阻止可执行输出。非整数主键生成 NOT NULL，复合主键保留顺序。默认值支持常量和 CURRENT_TIMESTAMP；任意默认表达式暂不支持；不支持 ON UPDATE 自动更新时间或数据库 UUID 默认函数，不静默丢失配置。表/列注释作为 SQL 注释输出。主键、索引与外键字段引用必须存在、非空；跨 schema/attached database 暂不支持，避免把 PostgreSQL schema 当成 D1 命名空间。

ORM 下拉增加 Drizzle (SQLite)，输出 drizzle-orm/sqlite-core 的 table、columns、主键、索引和外键。生成合法且稳定的 TypeScript 名称，字符串用 JSON 编码；原始 SQL 表/字段名保留。跨表引用需对应模型齐全，提供整组 schema.ts 导出；单表无法解析的关系报出原因，不能丢外键后给出貌似完整代码。不支持的类型或配置明确阻止输出。现有其他 ORM 对 SQLite 不作未经验证的承诺。

“SQLite / D1 导出”从选中的 SQLite 表导出 0001_init.sql、schema.ts 和使用说明；不创建用户云资源，不接收 Cloudflare token，不自动执行迁移。初始化目标为新数据库；支持自引用和已选对象之间的关系，缺失引用报错。表/索引命名冲突按 SQLite 的全局命名规则检测。

能力门禁：SQLite 不进入 SQL 解析的请求契约和数据库选项；DDL 对比仍可显示差异，但自动迁移/回滚明确返回手动迁移提示；隐藏授权和不适用存储配置；不生成 GRANT、COMMENT ON、CREATE OR REPLACE VIEW 或存储过程。视图仅支持 CREATE VIEW。既有 MySQL/PostgreSQL 工具维持原方言限制。SQLite 不扩展 AI 功能。

验证依据：SQLite CREATE TABLE、AUTOINCREMENT 官方文档；Drizzle SQLite 列类型和约束官方文档；Cloudflare D1 migrations 文档。单测使用真实 node:sqlite 执行建表、唯一/复合键和外键操作，验证输出而非只比较字符串。Drizzle 输出通过真实 Drizzle SQLite 元数据检查；不在应用运行时引入 Drizzle 依赖。

## 5. 字段影响分析

入口：数据库工具中的“影响分析”。选择快照范围、目标表和字段，展示依赖对象清单及关联字段。包括目标表的主键/索引、出向/入向物理外键与逻辑关系、分区列与可识别分区表达式、Citus 分布字段和 Hive 聚簇列。关系按完整字段组显示，不把复合外键拆成独立关系；分别标明“数据库约束”和“业务关联”。支持下载 Markdown 报告。

只按当前方言的标识符规则和完整 Schema 名解析，不跨数据库混淆同名表，不假设未限定引用指向任意 Schema。重复表/字段的歧义输入拒绝。清楚展示检查表数、未分析的视图与选集外关系；无发现只表示本次范围无已知依赖。首版提供可访问的关系清单，无需再建立一个图编辑器。影响结果不自动修改任何表。

核心 analyzeFieldImpact(tables, tableKey, fieldName) 返回结构化依赖与范围说明；界面派生结果，不保留过期分析缓存。复用字段表达式识别器而非新增正则解析 SQL。任意视图 SQL 和应用代码引用不在首版自动分析范围内。
