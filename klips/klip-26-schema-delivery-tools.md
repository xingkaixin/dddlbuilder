# 数据库文档、结构对比与关联测试数据

日期：2026-09-17

## 目标与实施范围

让已有数据库的维护者、接手项目的成员和测试人员直接完成三个任务：交付结构文档、核对两个环境的结构、准备可重复的关联测试数据。全部复用当前表结构模型，不引入 AI、数据库连接凭据、远程执行或新的持久化协议。

本轮交付完整的首版工具。长期文档托管、多人审批、自动执行迁移、大规模压测造数属于后续独立需求。

## 公共入口与交互

- 顶栏增加“数据库工具”，空工作区提供同一入口。工具在没有打开表和未登录时仍可使用。
- 使用独立的大尺寸工具弹窗，包含“数据字典”“结构对比”“关联测试数据”三个入口，按需加载。
- 文档与测试数据支持读取当前账号或匿名工作区的已保存表，也支持直接粘贴／上传 SQL。SQL 导入仅作为本次工具的输入，不写入编辑器和工作区。
- SQL 解析沿用当前服务和大小限制，显示解析失败的语句；存在失败时不产生可能误导用户的完整结果。输入改变后清除旧结果，避免导出过时产物。
- 已保存表通过显式勾选使用；重载时保留仍存在的选择。读取失败提供重试，切换账号或关闭工具后丢弃临时内容。
- 工具数据只在本次打开期间存在。导出后可离线使用；SQL 输入会发送到现有 SQL 解析服务，界面明确告知。
- 中、英、日三种语言一致支持。表名、字段名、用户注释和 SQL 保持原文。

### 布局与视觉

沿用现有主题变量、字体、圆角和控件。标题与动作固定在顶部；选择／输入区与结果区有明确分组。宽屏左右分栏，窄屏上下排列，长字段与代码在内部横向滚动。没有装饰性动效。

```text
数据库工具                                      关闭
数据字典 | 结构对比 | 关联测试数据
说明、数据来源与配置                 生成／导出动作
──────────────────────────────────────────────
输入／表选择                         结果阅读区
```

## 功能一：多表数据字典

### 用户流程

1. 从已保存表选择一组表，或解析一份 SQL。
2. 填写文档标题；默认“数据库数据字典”。
3. 生成阅读视图，使用搜索框检索表名、表注释、字段名、字段说明和枚举。
4. 导出 Markdown 或独立 HTML。HTML 包含样式和本地搜索，不依赖网络或第三方资源，可直接交付给同事。

### 文档内容

- 目录：数据库类型、Schema、表名、表说明和字段数。
- 字段：类型、可空性、主键、默认值、更新策略、说明、逻辑枚举。
- 索引：名称、类型、字段及排序。
- 关系：源字段、目标表／字段、物理或逻辑关系、基数与业务说明。选集之外的目标明确标为外部引用，不伪造为已包含表。
- 字段标准：已关联标准的业务名称、定义和单位；当前浏览器缺少标准时显示缺失状态。
- 关系导航以表和字段链接表达，首版交付可读的关系清单，不新增复杂图形渲染依赖。

### 数据规则

- 使用选中表的已保存状态；未保存的编辑必须先保存后才能从工作区读取。
- 每张表生成与用户名称无关的内部锚点，避免同名表、特殊字符和注入问题。
- HTML 转义所有用户输入，用户内容不能进入可执行脚本；Markdown 转义表格分隔符、HTML 和换行。
- 搜索仅影响阅读，不改变导出范围。输出保持选择时的快照。

### 验收

- 包含中文、同名不同 Schema、逻辑关系和枚举的多表输入能正确阅读和导出。
- HTML 离线打开可搜索；恶意注释按普通文本显示。
- 空选择不可生成；加载失败不显示为“没有表”。

## 功能二：两份 SQL 的结构对比

### 用户流程

1. 选择同一种数据库，首版支持 MySQL 和 PostgreSQL。
2. 在“当前结构”和“目标结构”粘贴 SQL 或选择文件，两个输入允许一侧为空以表示空数据库。
3. 解析两侧，出现不支持或失败语句时展示错误，不继续生成迁移。
4. 按 Schema 和表名匹配，显示新增、删除、修改和未变更数量。选表查看字段、索引、外键、注释等变化。
5. 对同表内删除／新增的字段，可显式建立重命名映射；系统不根据相似名称自动认定重命名。
6. 导出 Markdown 对比报告和正向 SQL。用户输入或匹配规则变化后重新计算。

### 对比与 SQL 规则

- 复用现有标识符语义和 diffPersistedState。顺序、格式和无关编辑器状态不构成结构变更。
- 同侧重复的完整表名拒绝比较；数据库类型固定一致。
- 新增表生成 CREATE，删除表生成 DROP；已有表复用 ALTER 生成器。
- 跨表外键采用先移除受影响约束、执行表和字段变更、再添加约束的顺序。新表先建表后建外键，循环引用不依赖建表顺序。
- SQL 明确标注删除表／字段的数据丢失风险。结构脚本不恢复数据、不替代线上数据检查。
- 已有生成器判定为手动迁移的变化，在报告中列明；不能把只生成了部分 SQL 的结果标成完整迁移。对未支持的迁移阻止 SQL 下载，保留差异报告。
- 不提供数据库执行按钮。首版不增加整库自动回滚承诺。

### 验收

- 格式变化得到零差异；新增／删除／修改多表报告完整。
- 显式字段重命名输出 RENAME，而非 DROP + ADD。
- 跨表外键的删除、重建次序正确；不支持的输入不能被静默忽略。
- 导出和当前输入一致；解析期间防止重复提交。

## 功能三：多表关联测试数据

### 用户流程

1. 从工作区或 SQL 选择表，配置每表行数和固定种子。
2. 生成前检查关系目标是否包含、字段类型是否支持、主键／唯一约束是否能满足，以及依赖图是否有循环。
3. 生成后显示每表行数和预览，支持下载 INSERT SQL 和按表分组的 JSON。
4. 相同表定义、行数和种子产生相同的数据及输出；改变种子产生另一批数据。

### 约束与范围

- 每表 1–1000 行，总计最多 10000 行、250000 个字段值；在生成前检查限额。
- 父表先生成；外键从真实生成的父行取值，复合外键整组复制。物理外键必须满足引用，逻辑关系作为可选生成关联由用户明确启用。
- 主键和唯一索引按列组检查，不能只检查单列；冲突通过有界重试解决，无法满足时解释具体表和约束，不交付残缺结果。
- 一对一关系受唯一性限制；子表数量超过可用父键数量时明确报错。
- 非空、长度、常用整数范围、小数精度、逻辑／原生枚举参与生成。日期基准固定；不使用当前时间作为隐含随机输入。
- 首版支持常用整数、decimal/numeric、浮点、字符／文本、布尔、日期时间、UUID、JSON。不支持的类型、默认值机制或不能可靠执行的约束需明确报错。
- 首版拒绝循环依赖／自引用、缺失目标、无法可靠处理的重叠外键和不兼容引用，提示用户调整选集或模型；不通过禁用外键检查绕过约束。
- SQL 使用目标方言的标识符和字面量转义；输出插入顺序与依赖顺序一致。首版 INSERT 支持 MySQL 和 PostgreSQL，其他方言不宣称可执行。
- 既有单表 Mock 保留，不改变其生成语义。新工具是有约束的独立批量任务。

### 验收

- 用户、订单、订单明细的外键全部可解析，主键和唯一键没有冲突。
- 固定种子可重复，切换种子有变化。
- 复合外键、枚举唯一键耗尽、循环、遗漏父表和不支持类型有可操作的反馈。
- SQL 不把 null 变成字符串，不丢失 bigint／decimal 精度，不输出不可转义文本。

## 实现边界与提交

1. `docs: Design schema delivery tools`：本设计。
2. `feat: Add database dictionary exports`：公共工具入口、输入与选择、文档生成和安全导出。
3. `feat: Compare SQL schema snapshots`：多表对比、重命名、迁移排序和报告。
4. `feat: Generate relational test datasets`：确定性生成、约束检查和导出。
5. `docs: Document database delivery tools`：三语指南与验证中发现的必要集成修正可按职责另行提交。

核心算法按现有包职责放置，UI 只组织输入和结果。只引入实际复用的共享函数，不预建导出插件系统或任务框架。

## 验证计划

- 为文档转义、结构比较／跨表依赖和关联数据约束添加行为测试。
- 为三个完整用户流程添加端到端测试，覆盖导出与关键失败反馈。
- 运行 `pnpm format`、`pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm run test:e2e`。
- 浏览器检查工具宽屏和窄屏的分组、对齐、滚动和暗色一致性。
- 所有提交保留在 main；本次不包含推送或部署。
