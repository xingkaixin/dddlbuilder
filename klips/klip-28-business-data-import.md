# 业务数据导入：可行性评估与功能设计

日期：2026-09-17。用户授权先评估、设计，再直接在 main 实施，分步提交；完成本地测试后 push，最终提交的 CI 全部通过后完工。

## 1. 用户任务与范围

用户收到真实业务 CSV / Excel，希望生成新表及导入 SQL，或在导入已有表前找出错误。已有“导入数据”读取字段定义清单，保留该功能；新增独立的“业务数据导入”，避免把业务记录当成字段定义。

本次交付三个连续任务：读取数据并确认字段映射；按目标结构校验所有记录；导出完整脚本或错误清单。导入配置可命名保存及 JSON 导入/导出，便于重复处理同一来源。

不涉及 AI、数据库连接、执行 SQL、上传业务记录、多人数据编辑、后台 ETL 或其他此前讨论的产品方向。

## 2. 可行性评估

| 项目 | 已确认基础与约束 | 结论 |
| --- | --- | --- |
| 部署 | React/Vite 静态资源 + Worker API，D1/KV/DO 承担账户和结构存储 | 通过。功能在浏览器运行，不新增服务、绑定、迁移或凭据 |
| CSV/粘贴 | 当前解析器针对字段清单；业务文件需处理引号、换行、空字段和物理行号 | 通过。独立解析边界，支持 UTF-8 CSV、TSV、分号分隔，明确选择分隔符 |
| Excel | 已有 SheetJS 与压缩包资源防护 | 通过。复用依赖与防护，仅 .xlsx，选择单工作表；拒绝公式、合并单元格、错误单元格和不可靠大整数 |
| 类型推断 | 原值必须保留；编号前导零不能被转换成数字 | 通过。扫描全部数据，保守推断，用户可修改类型；混合/未知内容回退文本 |
| 离线校验 | 可以检查值、类型、范围、长度、空值、文件内键重复；不能查询真实数据库 | 部分通过。明确校验范围，外部约束保留提示，不声称保证实际导入成功 |
| SQL 输出 | 现有 ddl-core 负责方言与标识符；新输入必须保证值作为字面量而非 SQL | 通过。限定 MySQL/PostgreSQL，精确数字按字符串处理，完整校验通过才输出 INSERT |
| 配置复用 | 浏览器已有本地配置存储模式 | 通过。保存映射与格式，不保存原始记录；坏配置不替换当前配置 |
| 响应与资源 | 文件解析、Excel 解压及全量校验可能占用主线程 | 浏览器后台线程处理任务；切换输入/关闭时可取消，旧结果不得覆盖新输入 |

首版资源范围：CSV/粘贴最多 2 MiB，xlsx 最多 5 MiB；单工作表最多 5000 条数据、100 列、100000 个单元格；单元格最多 10000 字符。拒绝超限，不截断后宣称完整。Excel 沿用压缩包展开限制。配置最多 50 份，每份 JSON 最大 256 KiB。

不增加依赖。没有新 Cloudflare 配置和云资源成本；新增的是前端包、浏览器内存与确定性计算成本。增长与付费效果尚无用户数据证明，不作为可行性通过的理由。

## 3. 输入与数据保真

- 入口为“数据库工具 → 业务数据导入”。支持文件或粘贴文本，第一条记录为表头。CSV 分隔符选择逗号、制表符或分号；引号内换行和双引号转义按 CSV 语义读取。
- 表头去除首尾空格，拒绝空白及重名；数据值默认不去除空格。空记录忽略，行号保留来源位置。每条记录列数必须匹配，不能静默补齐/丢列。
- 所有数据进入校验前保持字符串；空值转换由用户选择。字面文本 NULL 不自动转空。日期格式提供 ISO、DD/MM/YYYY、MM/DD/YYYY，拒绝无效日期，不猜测地区格式。
- Excel 首行是表头，空白行跳过；工作表可选择。真实日期单元格转换成 ISO，保留文本单元格原值；整数越过安全精度范围时拒绝并说明应在源文件中改为文本，不能修复已经丢失的数字。
- 公式不执行，也不使用可能过时的缓存结果；合并区域需用户在源文件展开。原始内容不进入日志、账号同步或配置导出。

## 4. 目标与映射

### 新表

选择 MySQL/PostgreSQL、表名及可选 Schema。首次读取后每个源列生成一个字段，用户可以改名、修改 SQL 类型和可空性，或忽略列。非法源列名生成可编辑的 column_N 名称；不擅自推断主键或业务唯一性。

推断顺序：布尔文字、无前导零整数、精确小数、有效 ISO 日期/日期时间、文本。整数超出 BIGINT 范围保留文本；小数计算精度和小数位，不经 JS Number。文本按完整值长度推断；无法可靠推断的列使用文本。空值策略和日期格式变化后允许重新推断，但不会静默覆盖用户修改。

### 已有表

复用已有表来源选择器，选择且仅选择一张 MySQL/PostgreSQL 表。结构来源可以是保存表、结构快照或 SQL；SQL 结构解析仍使用现有 API，实际业务记录始终留在本地。

每个目标字段选择源列或“不提供”。同名源列默认匹配，未映射源列明确显示为忽略。字段类型和约束来自选中的真实结构，不可在映射面板改写。未映射的必填且无默认字段报错；自增/默认值字段允许省略。显式映射后的空值不能被偷偷替换成默认值。

## 5. 校验与 SQL

逐行校验目标映射，输出来源行号、字段、原值、原因。检查支持的整数范围、decimal 精度、字符长度、布尔、日期时间、UUID、JSON、NOT NULL、逻辑枚举，以及文件内主键/唯一索引组合重复。未知类型、无法表达的索引或结构阻止输出，不按文本猜测。

文件内唯一检查使用规范化数值/日期和文本原值；明确不模拟数据库排序规则，也不检查现存数据、触发器、外部 CHECK 和外键目标。已有表与物理外键相关的范围提示保留在结果中。PostgreSQL 自增列显式赋值时提示序列位置需要自行核对。

新表输出 CREATE TABLE + INSERT，已有表仅输出 INSERT。SQL 使用目标方言的标识符引用和明确的字符串转义；所有输入只作为数据字面量。bigint/decimal 保留精度，拒绝 NUL。使用 PostgreSQL E 字符串和 MySQL UTF-8 十六进制文本表达式避免反斜线模式改变数据。按有限行数分批 INSERT；不生成 DROP/DELETE、覆盖写入或自动提交执行动作。

有错误时不能下载部分成功 SQL；可以下载完整错误 JSON。结果预览只显示前几行和有限长度脚本，明确这不影响完整下载。更改源数据、目标、映射或格式立即使结果失效。

## 6. 配置复用

配置包括版本、名称、目标模式及名称/方言、源列到字段的映射、新表字段定义、日期格式、空值和空格策略。已有表配置应用时核对当前目标身份，从当前结构重新取得字段定义；已删除字段和缺失源列报错，不按列位置套用。

本地保存、显式删除、JSON 导入/导出。名称相同不静默覆盖；加载只应用配置并清除结果，必须再次校验。原始行、文件名、错误原值和 SQL 不进入配置。浏览器存储失败显示错误，已有配置不被清空。

## 7. UI 与模块设计

界面依次为“1 数据来源”“2 目标与列映射”“3 校验与导出”；同一页面保留上下文，主操作随读取/校验进度变化。复用现有表单、按钮、Tabs 和表格样式。映射表在窄屏局部横向滚动，页面不横向溢出。错误不只靠颜色，提供文本、行号和完整清单下载。

- ddl-core/data-import：纯类型推断、字段值校验、目标结构转换、脚本生成。没有浏览器、Worker bindings 或数据库依赖。
- Web business-data：文件/文本读取、Excel 适配、后台任务生命周期、本地配置边界。
- Web components/data-import：数据来源、映射、配置和结果 UI，主组件拥有输入与结果失效规则。
- 三语界面和用户文档同步更新，修正旧文档把字段清单说成业务数据推断的描述。
